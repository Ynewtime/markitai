# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [1.2.1] - 2026-10-10

### Added

- **A new `markitai serve` workbench.** The web UI is now the workbench markitai's Rust implementation uses too, so both get the same UI from here on. A sidebar with **Convert**, **Conversions** and **Settings** (Models, Appearance, Access token; a bottom bar on a phone, where Settings is one list with Docs and GitHub). Files and folders are staged with upload progress before you press **Convert** (on a phone, Options, Upload and Folder are compact icons), and combine with pasted URLs into one submission. **Conversions** is one list of every item, grouped by submission and named after the folder or `.urls` list it came from, with name and status filters, and a **New conversion** button that leads back to Convert. A name too long for its place is shortened in the middle at folder boundaries, keeping the host and the extension (`/slow/annual-reports/2026/…/s5.html`), with the whole name in its tooltip. A conversion opens in a window centred over the list (its expand button or F makes it full screen and back, a choice each browser keeps; always full screen on a phone) with one row of tabs, and ↑/↓ move to the previous or next item: **Details** shows, in the same centred column as Preview, its status, source and output sizes, models, cost, options, notices, how long it is kept and the start of its result. **Preview** (with its views, Rendered, Source, Diff and Files, and Base | LLM at the end of the tab row, or in one compact switch where they do not fit, as on a phone) draws SVG drawings embedded in the Markdown, sanitized so nothing in them runs a script or loads anything; **Compare** shows the original next to the Markdown: PDF pages (with the heading or table under the pointer outlined), images, HTML and text documents, or the page screenshots a conversion saved. For a web page, Compare shows the page as the server fetched it, in a sandboxed frame: with the site's own pictures, style sheets and fonts (your browser loads them from the site over HTTPS), none of its scripts, links opening in a new tab, beside its screenshot when one was saved, with **Open the page** in the header. The header's **Download** opens Preview's **Files**: the original first (tagged "Original", or "Page as fetched" for a web page), then every result file, each with its own download, the total, and **Download all (.zip)**, which holds the result's files and its original. Notices are one-line strips at the bottom of the window (above the bottom bar on a phone) that leave by themselves; a failed action on one conversion (Retry, Delete, Download, …) is reported in that conversion's Details, and lasting conditions (a conversion that ran without a model, a history that could not be saved, a missing token) are shown where they apply instead of in banners across the page. **Add models** opens a provider picker: one search over provider names and model prefixes (`ollama_chat` finds Ollama), the common providers as tiles with their brand marks, and the others under group filters (Clouds, Inference, Gateways, Local, Subscriptions, Model makers). It offers every provider markitai routes through the installed LiteLLM, about 90 instead of 8: Mistral, Groq, Together AI, Fireworks, Amazon Bedrock, Hugging Face, LM Studio, vLLM and the rest, each with the address it uses and the key variable LiteLLM reads, its model list where the provider publishes one and model IDs typed by hand where it does not. Where LiteLLM's own default address is out of date or missing, a new connection stores the provider's documented one: without it, `ai21/`, `lm_studio/` and `xinference/` models sent their key to api.openai.com, and Perplexity models went to the Sonar chat completions endpoint Perplexity announced it would retire on 2026-09-27 (they now use its Router API). GradientAI and Morph are not offered: LiteLLM refuses the requests markitai sends them. A provider is listed once: any provider whose key variable is set where the server runs (not only OpenAI, Anthropic, Gemini, DeepSeek and OpenRouter) appears under Saved, folded into a connection that already uses that variable; each saved row says how it authenticates (`Using DEEPSEEK_API_KEY`, `Key saved`, `No key`), the common tiles mark the providers already added, and a key field names the variable that would serve it. **Settings → Access token** can regenerate the token: the old one stops working at once (in every other tab and on every device, also on this machine, with its unused download links), and the new one is shown once, with its sign-in link and a QR code drawn in the page. Preview, Compare and the excerpt in Details show a conversion's own extracted images (they showed "[Image: preview unavailable]"), read through a route that serves only that conversion's listed raster images, inline and sandboxed. Japanese joins English and Chinese. Large results stay responsive: the preview of a 20,000-row spreadsheet shows its first 500 rows in about 0.15 s (**Show all rows** adds the rest), where the 1.2 app took 3 s with the tab frozen for 2.5 s and built 160,000 page elements. A long document is drawn a piece at a time, laying out only what is near the screen, and kept while you switch tabs: a 460 KB EPUB result with 160 pictures shows its beginning in under 0.1 s at phone CPU speed without freezing the page, and Diff compares documents that size, folding the unchanged stretches. A document with four or more headings has a table of contents beside it (on a phone, a button opens it as a sheet) that marks the section being read. The page first draws in about 0.1 s instead of 0.2 s.
- **Stop remaining**: a running submission's items that have not started can be stopped; the ones already converting finish, and stopped items can be retried later (`POST /api/jobs/{job_id}/cancel`). On a phone it stays a button in the header of the full-screen window that covers the list (a submission's, a waiting item's, or Summary), and in Conversions it takes a row of its own under the title and the status.
- **`.urls` lists in the web UI**: an uploaded `.urls` file becomes URL items, read like the command line reads it (one URL per line with an optional output name, `#` comments, or a JSON list). `markitai serve` used to refuse it as an unsupported format.
- The serve API for the workbench: the original of an item (`GET /api/jobs/{job_id}/items/{item_id}/original`, its `/file`, page images `/pages/{n}?width=` rendered with PyMuPDF and Pillow, and a PDF page's positioned text lines `/pages/{n}/text`), single-use download tickets (`POST /api/download-tickets`), `GET /api/history?include=items`, result excerpts (`?max_bytes=`), one item's ZIP with its original (`GET /api/jobs/{job_id}/items/{item_id}/archive`), a kept web page for the workbench's sandboxed frame (`…/original/view`; a URL item now keeps the page it was converted from, up to 10 MiB, when markitai fetched it itself: not for Jina, Defuddle or a fetch-cache hit), `POST /api/access-token/regenerate`, a job `label`, and on every item `error_code`, `pricing`, `models`, `source_size` and its saved `options`. `GET /api/capabilities` lists the `features` the server implements, its `docs_url` and `source_url`, the history retention and whether Cloudflare can be used. A browser opening an address the workbench does not have gets its "Page not found" view (status 404) instead of a JSON error.
- **Several conversions deleted at once, user tokens and Edit config in `markitai serve`** (workbench 1bc3d25). **Conversions** has a box at the left of every row and submission header (Space checks the focused row, Shift extends, Ctrl/⌘+A checks every listed row, Escape clears; on a phone, **Select** mode), a bar with the count, **Select all** and **Delete**, and one confirmation; the server deletes them in one request. **Settings → Access token** creates user tokens with a name, each shown once with Copy, its sign-in link and a QR code, and listed by its last characters with when it was last used and **Revoke**. A user token converts files and URLs and sees, downloads, stops, retries and deletes only its own conversions; Models, Access token and Edit config need the admin token (the server's own token, or this machine without a token, as before), and the admin sees everyone's conversions, a revoked user's too. Revoking signs the token out at once, with its download links and live progress, also on this machine. Only a SHA-256 digest of each user token is kept, in `~/.markitai/serve/access.json` (owner-only, never the config file), so they survive restarts and a regenerated admin token; the server's log names a token by its label, never the token. **Settings → Edit config** shows the configuration file as text with its secrets masked by the rule `markitai config show` redacts with (`sk…7890`; an `env:` reference as it is), checks the JSON as you type (line and column), reviews the change as a line diff and saves exactly that text, layout, key order and line endings kept (a file written on Windows stays CRLF, a missing final line break stays missing); a masked value left where it was keeps the stored secret, and a file changed meanwhile is refused with **Load current file**. Models and connections apply at once; the page says when the other changes need a restart. Pictures on the web (absolute `https://` addresses in the Markdown) now show in Preview, Compare and the Details excerpt instead of a placeholder, and Compare links a web page with its Markdown block by block: hovering a heading, paragraph, list item, table or picture on either side outlines both.
- The serve API of workbench contract v1.13: `POST /api/history/delete` (`{jobs?, items?}`, 1 to 1000 entries, each deleted as its single `DELETE` route would, every outcome in the answer), `GET`/`POST /api/access-tokens` and `DELETE /api/access-tokens/{id}` (admin only), `GET`/`PUT /api/settings/config` (`{expected_revision, text}`; 409 `stale_revision` or `config_changed`, 422 `invalid_config` with the line and column or the validator's words), and in `GET /api/capabilities` the caller's `access` (`admin` or `user`) and the features `batch_delete`, `user_tokens` and `config_edit`. A user token is 403 `settings_forbidden` on the settings and token routes and 404 `job_not_found` on every conversion it did not create; history, the history archive, batch delete and download tickets are limited to its own.
- **Compare knows what a web page's capture shows, and links its screenshot block by block** (workbench e6b0e39, contract v1.14). A URL item now records how usable its kept page and its screenshot were when they were taken: the page's content, an empty page (blank, or one that only asks for JavaScript), or a verification, captcha, bot check or login page shown instead of the content (the rules Rust uses, plus Python's own markers). Compare offers only a view that shows the page, and when neither does it says why ("The site showed a verification check…", "The page was blank…") and offers to open the page. When the browser takes a page's screenshots it first records where the page's headings, paragraphs, list items, tables and pictures are drawn, with the script the workbench ships (`capture/page-blocks.js`, run unchanged), so hovering a block on the screenshot or in the Markdown outlines its counterpart. A page the browser loaded for its text, with no screenshots asked for, also keeps compare screenshots (JPEG quality 70, tiles of the screenshot tile height, at most 20 tiles and 50 megapixels; about 130–160 kB per 2000 px tile of a text page): Compare shows them, they are never output, never in a result or an archive and never sent to a model or OCR. A short page that shows a picture or a media player counts as content, not a blank page (a picture post with a one-line caption is framed); a pixel, a hidden or placeholder picture does not count. A retry replaces them, deleting the item or its conversion removes them; a retry that loaded no page, or whose browser was shown a verification or blank page, keeps the earlier ones.
- The serve API of workbench contract v1.14: the original descriptor's `capture` (`{page, screenshot}`, each `{state, text_length, title, reason}` or null; null for uploads) and `blocks`, `GET /api/jobs/{job_id}/items/{item_id}/original/blocks` (the block boxes, 404 `original_unavailable` without them), and compare screenshots as a URL item's `pages`. They are kept beside the page in the job's `snapshots/` folder as `<item>.capture.json`, `<item>.blocks.json` and `<item>.shots/<n>.jpg`, owner-only; a conversion recorded before has its kept page judged when asked.
- **Users' own models and models the admin shares in `markitai serve`** (workbench 36583fe, contract v1.15). A user token's **Settings → Models** is now the admin's Models page for its own models: Add models with the provider picker, Test, Edit, Delete and weights, then **Shared by the admin** (read only: model, provider, weight). Each of the admin's saved models has a **Private | Shared** switch (private by default, saved as `"model_info": {"share": "shared"}` in the configuration file, so Edit config shows it). A user's conversions use one pool: its own models, then the shared ones, picked by weight, a failed request moving on to another model of the pool; prompts, budgets and the cache stay the admin's, and the job shows which model ran and its cost. A user with neither gets no LLM options ("Add a model in Settings → Models…") and a request for them is refused; the server's environment keys and detected models never serve a user. A shared model's key and address never leave the server: a user sees what it is, never where it is served. A user's models are its own: kept in `~/.markitai/serve/user-models/<token id>.json` (owner-only, never the config file), its keys shown masked only, and only models with the user's own key or the address of a server that takes none, never a provider that signs in with the server's own account (subscriptions, Vertex AI, watsonx, GigaChat, SageMaker, Bedrock without a key) or an address on the server's own machine. **Access token** rows say how many models each user has, and revoking a token deletes them with their keys.
- The serve API of workbench contract v1.15: `/api/me/models*` for a user token (403 `user_token_required` for anyone else): `GET /api/me/models` (`UserModelsView`: the user's own deployments, `shared` as `{id, model, provider, weight}`, `limit` 50), `GET …/providers`, `GET …/providers/{id}/credentials`, `POST …/model-discovery`, `POST …/test`, `POST …/deployments/batch`, `PATCH`/`DELETE …/deployments/{id}` and `…/providers/{id}`, with the settings routes' bodies, revision rule and statuses, refused with 422 `server_credentials`, `key_or_address_required` or `server_address` or 409 `model_limit` before anything is saved or sent; `share: "private" | "shared"` on `PATCH /api/settings/llm/deployments/{id}` and on every saved deployment; `model_count` on `GET /api/access-tokens`; `features.user_models` and, for a user, `llm` describing its pool in `GET /api/capabilities`.
- **Users weigh and test the models the admin shares, and edit their own models as text** (workbench 6021fb8, contract v1.16). Each row under **Shared by the admin** has **Test** and a weight of the user's own: click the weight, type a number, Enter (or leave the field) saves, Escape cancels. The weight applies to that user's conversions only; 0 turns the model off for that user ("Off for your conversions (weight 0). Other users are not affected."), and **Use the admin's N** follows the admin again. Test runs on the server with the admin's settings and says only whether the model passed and why not, never the provider's words, address or key; a user tests one shared model at a time and at most six a minute (the admin's key pays). The admin's and a user's own weights are edited in place the same way on the Models page. A user token gets **Settings → Edit config** for its own models: one JSON document of its models, connections and shared-model weights, keys masked, with the admin page's check, Review and conflict flow; the server's configuration file is never shown to a user or changed by one. The sidebar (and the phone's Settings list) shows which build answers: `1.2.1 1a2b3c4 10-15 09:30`, the version, the commit, `-dirty` for a build with uncommitted changes, and the build time in the viewer's time zone (a source checkout has no build time). A video written as a linked poster (`[![…](poster)](https://…/clip.mp4)`) plays in Preview and Compare, nothing loaded until played and no referrer sent. Warnings list pages as ranges; a PDF whose pages are at least nine in ten without readable text says "This PDF is scanned: turn on OCR and convert again", and a model answer the page guards set aside is explained in plain words. A table whose row was broken by a line or paragraph separator renders as a table again.
- The serve API of workbench contract v1.16: `PATCH /api/me/models/shared/{id}` (`{expected_revision, weight}`, `weight` a whole number or null; 404 `settings_entry_missing` for a model no longer shared, 409 `stale_revision`; kept in the user's file as `shared_weights`), `POST /api/me/models/test` with `{shared_id}` alone (`{ok, detail}` or `{ok: false, reason, detail}`; 429 `provider_busy` with `Retry-After` beyond the bound), `GET`/`PUT /api/me/config` (a `ConfigDocument` with `path: null` and `origin: "user"`; 422 `invalid_config` for text that is not the document's shape, the Models routes' own refusals for what a user may not save, `restart_required` always false), `default_weight` on every `SharedModel`, and in `GET /api/capabilities` `build: {version, commit, built_at, dirty}` for every caller and `features.user_config`. Wheels and sdists carry `markitai/_build_info.py` (the short commit, the build time or `SOURCE_DATE_EPOCH`, and whether tracked files had changes), written by the build hook in `hatch_build.py`, never into the source tree; a source checkout reads its git state instead.

### Changed

- **The framed web page in Compare shares the workbench's origin** (`…/original/view` answers under `sandbox allow-same-origin allow-popups allow-popups-to-escape-sandbox; default-src 'none'; …`), so the workbench can read the page's blocks and link them with the Markdown. The page still runs nothing: no script, inline handler, `javascript:` link, meta refresh, form, frame or object (checked in Chromium by `scripts/sandbox_probe.py`). The workbench's own pages allow `https:` pictures (`img-src 'self' blob: https:`) and `https:` videos (`media-src https:`).
- **Page lists in warnings read as ranges, and the scanned-page notice counts the document's pages**: `[PDF] plan.pdf: 4 of 120 pages look scanned/garbled (pages 3–5, 9); consider re-running with --ocr` (it listed every page: `pages 3, 4, 5, 9`), and the hidden-text, OCR and screenshot-extraction notices list pages the same way. A model answer the page guards emptied now says `the model's answer did not match the document page by page, so the page drift guard set it aside` instead of `LLM answer text was discarded by the page drift guard`.
- **The React web app is retired.** `webapp/` and its build in `markitai/serve/static/` are gone from the repository and the package; the workbench is built in the markitai-rust repository and vendored under `markitai/serve/workbench/` with a manifest of every file's digest (`scripts/sync_workbench.py` refreshes and checks it), so neither Node nor Rust is needed to build markitai. What you notice: the layout above; settings are pages (`/settings/models`, …) instead of a dialog, and a conversion's preview opens in a window over the list (full screen on request) with its details and Compare; the 1.2 app's `/assets/…` addresses no longer exist. The wheel is 1.64 MB instead of 1.51 MB: the workbench ships each script both plain and gzip-compressed, so the server sends the compressed copy without compressing at request time.
- **An LLM request without a usable model is refused**: `POST /api/jobs` asking for LLM processing (`llm: true`, or a preset that turns it on) when no configured model can be reached now answers 422 `llm_unavailable` and stores nothing. It used to convert without the model and report success. A server configuration that enables LLM without models still converts without it, as before.
- **Cloudflare needs each request's consent in `serve`**: a job (or retry) choosing the Cloudflare strategy or files backend must carry the new option `"remote_processing": "cloudflare"` in the same request's options; the workbench asks before sending it, and without it the request gets 422 `remote_processing_confirmation_required`. It is refused for a caller the server does not trust, another machine without the token (403 `remote_processing_forbidden`), because it bills the server's Cloudflare account, and gets 422 `cloudflare_unavailable` when Cloudflare is not configured (`remote_processing_disabled` when the server runs with `MARKITAI_NO_REMOTE_FETCH=1` or `fetch.remote_consent: never`). The consent is never stored, so retrying such an item asks again.
- `markitai serve` errors carry a stable `reason` beside `detail` and `code` (`llm_unavailable`, `file_too_large`, `ticket_invalid`, …), which the workbench translates.
- **Job options are checked strictly**: in `POST /api/jobs` and in a retry, an unknown option key or a value of the wrong type is refused with 422 (`invalid_options` on a job, `invalid_retry_body` on a retry) instead of being ignored or converted; `"llm": "yes"` used to count as true. URLs are checked when submitted (422 `invalid_url`, `unsupported_url_scheme`) instead of becoming failed items, and a label longer than 120 characters or with a control character is refused (422 `invalid_label`).
- **A 422 explains itself in one sentence**: a request the schema refuses gets one sentence in `detail` naming each field and its problem (`invalid options: colour: Extra inputs are not permitted; llm: Input should be a valid boolean`, at most five), instead of pydantic's list of objects, and never the values that were sent, which may be an API key.
- **Results over 64 MiB are not sent as JSON**: `GET /api/jobs/{job_id}/items/{item_id}/result` answers 413 `result_too_large` for a Markdown result over 64 MiB instead of building a response that size; download the file instead, or ask for its beginning with `?max_bytes=`.
- An item still waiting for its provider batch (`--llm-batch`) can no longer be retried or enhanced from the web (409 `batch_pending`): that would pay for the same enhancement twice.
- The credentials endpoint also sends the masked key as `api_key`, the name the workbench reads, beside `api_key_masked`.
- PyYAML, beautifulsoup4, soupsieve, defusedxml, PyMuPDF, openpyxl, numpy and olefile are now declared dependencies. markitai imports them directly; they used to arrive only through other packages, so an upstream release dropping one could break `import markitai`.
- **The default DeepSeek model is `deepseek/deepseek-flash`** (DeepSeek V4.1-Flash), for `markitai init` and for a detected `DEEPSEEK_API_KEY`. DeepSeek retired V4-Flash on 2026-09-10 and routes `deepseek-v4-flash` and `deepseek-v4-flash-vision-exp` to V4.1-Flash only for the time being. A config that still names one of them (`markitai init` in 1.2.0 wrote `deepseek/deepseek-v4-flash`) gets a startup warning naming the new default; markitai does not rewrite it.
- **Current default models for the other providers**: with only that provider's key or subscription found, `markitai init` and the key detection now pick OpenAI `openai/gpt-6-luna` (was `gpt-5.6-luna`; $0.10/$0.50 per million tokens instead of $0.20/$1.20), Anthropic `anthropic/claude-haiku-5-5` (was `claude-haiku-4-5`; $0.10/$0.50 instead of $1/$5 for prompts up to 100k tokens), ChatGPT `chatgpt/gpt-6-luna` (was `gpt-5.6`), GitHub Copilot `copilot/auto` (was `claude-haiku-4.5`; Copilot's Auto model selection, the only choice on Copilot Free and Student plans since June 2026, billed at the rate of the model it picks) OpenRouter `openrouter/~anthropic/claude-haiku-latest` (was `google/gemini-3.1-flash-lite`; OpenRouter's moving alias for the newest Claude Haiku. Its catalog names Claude Haiku 5.5, at $0.10/$0.50, but on 2026-10-10 requests to it were still answered and billed as Claude Haiku 4.5, at $1/$5; set `openrouter/anthropic/claude-haiku-5.5` to pin the cheaper model) and Claude Code `claude-agent/haiku` (was `claude-agent/sonnet`; Claude Code's alias for its cheapest current model, Claude Haiku 5.5 in Claude Code 2.1.29x, which also uses up a subscription's limits more slowly). Gemini and DeepSeek keep their defaults. A config that names a previous default keeps working with no warning, since none of them is deprecated. LiteLLM 1.104.2 has no price for `claude-haiku-5-5`, so markitai carries its entry until LiteLLM does: its requests are priced and count toward `max_cost_per_document_usd` instead of being reported as unpriced. OpenRouter requests are charged at the amount OpenRouter itself reports for them, because the model behind an alias is only known from the answer, and LiteLLM 1.104.2 has no price for `anthropic/claude-haiku-5.5`.
- **`markitai doctor` says plainly whether markitai is ready.** It ended with "! Core check passed (3 required/configured checks passed, 2 non-blocking warnings)": a warning mark next to "passed", in jargon. The last line is now "✓ Ready. Not available (optional): Playwright, LibreOffice", "✓ Ready. Everything is available." or "✗ Not ready: fix LLM API first (see above)". Each fix is a command for this machine on its own line: Playwright's browser is installed with markitai's own Python (`python -m playwright` named whatever `python` was on PATH, which is not the environment `setup.sh` or `uv tool install` puts markitai in), with `--with-deps` on Linux; LibreOffice with the package manager of the detected Linux distribution instead of a block of apt, dnf and pacman lines that lost their indentation. A model whose provider key is not set (`deepseek/deepseek-flash` without `DEEPSEEK_API_KEY`) no longer passes: doctor names the variable and says how many models the run will leave out, and fails when no model is left. Keys that are set but used by no configured model are listed (`llm-api.unused_api_keys` in `--json`). The Claude Code row says whether Claude Code runs on a subscription or bills `ANTHROPIC_API_KEY` (it claimed "claude doctor passed", which markitai never ran), and the RapidOCR row says the default `ocr.lang: en` reads Chinese, English, Japanese and Latin-script text: RapidOCR's PP-OCRv6 recognizer is one multilingual model, so `en`, `zh` and `ja` read Chinese and Japanese scans alike; "lang: en (English)" suggested they would not be read.
- **`markitai init` says which keys it does not use and why.** With every provider key set and Claude Code signed in, it configured Claude Code, DeepSeek, Gemini and OpenAI and said nothing about `ANTHROPIC_API_KEY` and `OPENROUTER_API_KEY`. Leaving them out is deliberate (Claude Code's subscription serves Claude Haiku, which is also their default, so they would only split the requests with a paid route to the same model); init now prints one line per key it leaves out, with that reason. Updating an existing config adds a provider only when the config has no model of that provider, so a config naming the earlier default `claude-agent/sonnet` does not gain a second Claude Code entry.
- The MCP Registry entry runs the release it names (`uvx --from "markitai[mcp]==1.2.1"`) instead of whatever is latest on PyPI.
- Unused Python APIs were removed: `LLMProcessor.clean_markdown`, `get_usage`, `get_total_cost` and `reset_call_counter` (per-document usage stays in `get_context_usage`/`get_context_cost`), `LLMProcessor.enhance_url_with_vision`, the never-set `FetchResult.static_content`/`browser_content` fields, `BatchProcessor.process_batch` (with `markitai.batch.ProcessFunc`), `ImageProcessor.process_and_save_async`, `OCRProcessor.is_scanned_pdf`, `BaseConverter.can_convert`, `PromptManager.list_prompts`, `collect_user_notices`, `markitai.llm.MarkitaiLLMLogger` (it was registered as a global LiteLLM callback), and the never-raised `QuotaError`, `ProviderTimeoutError` and `SDKNotAvailableError`. `SingleFileWorkflow` now requires `processor=` and no longer takes `no_cache`/`no_cache_patterns`. The `prompts.url_enhance_system`/`url_enhance_user` settings and prompt files are gone too: no code path ever sent them, and a config that still sets them loads as before.
- `markitai serve` requires the access token for the LLM settings routes (`/api/settings/llm…`, including stored credentials) from every client, this machine included: any local program, or a page on another `localhost` port, connects over loopback too. The browser opened at startup and the printed token URL carry the token; with `--no-auth`, this machine still reaches the settings without one. A request with no client address is no longer treated as coming from this machine.
- **`markitai serve --no-auth` fetches URLs only for this machine**: a job or retry with a URL from another machine gets 403 `remote_url_forbidden`, for public and private addresses alike, as the shared workbench's API contract says. Other machines used to be limited to public addresses, which still let anyone who could reach the server use it to fetch pages. This machine still submits any URL, and other machines can still upload files; with token auth (the default) a machine that has the token keeps full access.
- After upgrading: the LLM cache key now covers the full text and the image bytes, so existing `cache.db` entries miss once after upgrading and the first run of an already-processed document calls the LLM again. `markitai serve` history now ages from when a job finished instead of from its directory's modification time, so history that finished more than seven days ago is deleted on the first start, even if its directory was touched recently.

### Fixed

- **Gemini 3.8 Flash and 3.6 Flash from 2027**: Google lists Gemini 3.8 Flash, 3.6 Flash and `gemini-flash-latest` on the Gemini API at introductory prices through December 31, 2026, and doubles them from January 1, 2027. LiteLLM 1.104.2 knows only the introductory prices, so from 2027 markitai would have reported half of what these answers cost, and `max_cost_per_document_usd` would have counted half. Answers from 2027-01-01 (UTC) on are now counted as unpriced, as in markitai's Rust implementation.
- **DeepSeek on Chinese public holidays**: DeepSeek bills Beijing time 09:00-12:00 and 14:00-18:00 on working days at its peak rates and every other hour, weekends and public holidays included, at half. markitai (through LiteLLM) charged a public holiday's working hours at the peak rates. It now uses the same rule as markitai's Rust implementation: a request is priced at the peak or off-peak rates when it was sent and answered within one period, and a weekday peak-hour request on a date not yet checked against the State Council's holiday schedule (checked: 2026-10-08 to 2026-12-31) is left unpriced rather than possibly overcharged, as is a request that crosses from one period into the other.
- **Claude Batch costs count prompt caching**: an `--llm-batch` result from Anthropic was priced from its input and output tokens alone, and Anthropic's input count leaves out the cached part, so cache reads and cache writes were missing from a batch's reported cost (1-3.5% low with a typical cached prompt, more with heavy caching). It is now priced like a live answer, 5-minute and 1-hour cache writes included, at half the list price.
- **Claude Sonnet 5.5 and GPT-6.1 Sol are priced**: LiteLLM 1.104.2, the release markitai depends on, lists neither model, so their requests were counted as unpriced: the summary said the cost was unknown and `max_cost_per_document_usd` could not count them. markitai now carries their price rows, as it already did for Claude Haiku 5.5, until a LiteLLM release lists them: the rows of LiteLLM 1.106.0.dev2, which equal the providers' published prices on 2026-10-11, Batch and prompt-cache rates included, and are the ones markitai's Rust implementation prices from.
- **`serve` no longer shows an unknown LLM cost as `$0`**: the web UI showed "$0" per item and in totals when the provider had no price for the model, while the item's own notice said the cost was unknown. Items and history now carry `pricing` (priced and unpriced requests, `cost_status`), and the workbench shows "Unknown" or "At least $x" instead.
- **Web downloads no longer put the access token in their URL**: "Download all" and other browser downloads opened `…?token=…`, which stayed in the browser history and download list. They now use a single-use link that expires after a minute (`?ticket=`, masked in the request log like `?token=`).
- **Models can be added from an environment card in `markitai serve`.** With `OPENAI_API_KEY` (or the Anthropic, Gemini, DeepSeek or OpenRouter key) set, Add models shows an "Using OPENAI_API_KEY" card, but loading its models or saving one answered "This saved provider connection no longer exists" (HTTP 404), and so did saving a model the server had detected from that key: the server looked for the card among the saved connections only. The card now stands for the provider's own key variable at the provider's own endpoint, as in the API contract and the Rust implementation: models are listed with that key, and a saved model stores the reference (`api_key: "env:OPENAI_API_KEY"`, no address), never the key itself, under one saved connection that then replaces the card. The key never goes anywhere else: an address sent with the card, a card for another provider than the model's, or a card id that names a variable or a provider without such a card (`env:AWS_SECRET_ACCESS_KEY`, `env:groq`) is refused with HTTP 422.
- **A model test in `markitai serve` says why it failed.** Testing a DeepSeek model on a server without `DEEPSEEK_API_KEY` sent the request anyway (LiteLLM sends one without a key when it finds none) and reported "AuthenticationError: litellm.AuthenticationError: AuthenticationError: DeepseekException - Authentication Fails (governor)", which read like a wrong key. A test now finds an unset key variable before sending anything, for every provider the workbench connects, and the workbench names the cause with what to do about it: **No API key** ("DEEPSEEK_API_KEY is not set on the server. Set it where markitai serve runs and restart the server, or add a key to this model's connection."), **Key rejected** (HTTP 401/403), **Model not found**, **Rate limited or out of quota**, **Provider unreachable**, **No answer in time** or **Provider error**, with the provider's own words, without LiteLLM's class names, under "Provider's message" (`Model connection returned HTTP 401: Authentication Fails (governor)`). The API answers as markitai's Rust implementation does: `reason` (`no_key`, `key_rejected`, `model_not_found`, `rate_limited`, `network`, `timeout`, `provider_error`) and, for a missing key, `key_variable` (the variable's name, never its value).
- `serve` offered Retry for files it cannot convert (`unknown.bin`); items now carry `error_code` (`unsupported`, `fetch_error`, `cancelled`, …) and the workbench offers Retry only where it can help. A tab without the token now asks for it instead of showing a raw header-syntax message.
- **An EPUB's pictures are saved with its Markdown.** The Markdown kept each chapter's own reference inside the book (`../Images/cover.jpg`), which resolves nowhere beside the output, so the pictures were missing from the Markdown and showed as placeholders in the `markitai serve` preview. A raster picture the book holds (PNG, JPEG, GIF, WebP) is now saved as one of the output's assets (`book.epub.0001.jpg`) and linked like a DOCX picture, so `--alt` and `--desc` describe it too; a remote, SVG, ambiguous or oversized one keeps its reference. A cover picture wrapped in SVG (the cover page Calibre, Sigil and Project Gutenberg write) and a cover only the OPF names are kept too, and a chapter whose file name the OPF percent-encodes (a Chinese file name, as Sigil writes it) is no longer skipped with all its text.
- **No `.llm.md` when no model succeeded.** A file could get a `.llm.md` and count as enhanced although no model answer was usable: an image whose model declined ("I'm sorry, I can't help with that") got that sentence as its description and alt text, and the refusal was cached; an answer the provider's content filter stopped was accepted; in screenshot-only mode, pages read as empty were dropped without a word, and in `markitai serve` a whole answer could be replaced by the extracted text (a PPTX's "Slide" markers never match the reading's "Page" ones) while the item still said enhanced. Now an answer counts only if it was finished (not cut at the output limit or stopped by a content filter), does not decline, and is not the original text put back; a refusal is never cached. When no request for a file produced such an answer, only the base `.md` is written and the item's warnings end with "No model succeeded for this document; only the base Markdown was kept." (the workbench shows it as one notice, in the same words as the Rust implementation); image answers that came with a failed document are dropped with it. Screenshot pages read as empty are named in a warning. In `markitai serve` an item lists only the models whose answers its result uses (none for a base-only result, whose cost still counts), and a failed Retry or Enhance keeps the previous result and records why (`rerun_failure`, also after a restart; an Enhance that stands clears it) with the actual cause instead of "LLM enhancement did not produce an enhanced Markdown result".
- **A failed Claude Code turn no longer becomes the model's answer.** When Claude Code could not answer (usage limit reached, login expired, an API error), it still returned the error text, and markitai took that text for the result: an image got a `.llm.md` whose description and alt text read "Claude AI usage limit reached", with no warning, and documents failed as "Invalid JSON" without the cause. The turn now fails like any other refused request (a usage limit as a rate limit, a refused login or balance as an error the user must fix), so the item keeps only its base `.md` and its notices say why, in single-file, batch, URL and `markitai serve` runs alike. A GitHub Copilot turn that ended without an answer no longer returns the text "None".
- **Claude Code requests are no longer billed to `ANTHROPIC_API_KEY` instead of your subscription.** Claude Code, run by the Agent SDK in non-interactive mode, sends `ANTHROPIC_API_KEY` whenever the variable is set, even with a Claude subscription signed in, so with the provider keys loaded every `claude-agent/` request was charged per token to the key, at the rate of the then default `claude-agent/sonnet`. With a subscription login (`claude login`, or `CLAUDE_CODE_OAUTH_TOKEN`), markitai now runs Claude Code with the variable hidden from it. A Claude Code signed in with nothing but that key is no longer taken for a subscription by `markitai init` and the key detection, which dropped the Anthropic API model in its favour: `anthropic/claude-haiku-5-5` uses the same key directly, without a Claude Code process per request.
- **Terminal output wraps under its text.** A long status, warning or summary line wrapped back to column 0 in the middle of a phrase (`markitai doctor`'s VLM OCR line, the budget warning "…leaves 10 of 10. Nothing" / "was sent: …"); it now wraps at word boundaries with a hanging indent and never splits a path, a URL or a command. Off a terminal, `doctor` and `init` output is no longer hard-wrapped at 80 columns either (one line per message, as stderr already was). A non-UTF-8 output stream (`PYTHONIOENCODING=ascii`, a Latin-1 locale) made every command fail with `UnicodeEncodeError` on the first status mark; it now gets ASCII marks (`+ x ! - * > o`), as do `TERM=dumb`, a Windows console that cannot process escape sequences (Windows before 10 version 1511, or the console host's "Use legacy console"), and on Windows a pipe or a file while the console's output code page is not UTF-8: Windows PowerShell 5.1 decodes a program's piped output with that code page, so at code page 437 `markitai doctor | Out-File -Encoding utf8 x.txt` wrote `Γ£ô` for `✓` and `ΓÇó` for `•`. After `[Console]::OutputEncoding = [Text.Encoding]::UTF8` (or `chcp 65001` in cmd) pipes and files get the Unicode marks, and so does output with no console attached (a service, a detached process), which has no code page to follow. Everything else keeps the Unicode marks `✓ ✗ ! • ◆ → ○` on every platform, as in markitai-rust: any console that takes escape sequences, which markitai switches on when they are off, and mintty (Git Bash). One run uses one set: when stdout or stderr needs the ASCII set, both get it. The text itself stays UTF-8. `NO_COLOR` turns off only the colour. Progress bars, help panels, boxes and spinners are drawn with the same choice as the marks (a classic console window showed `✓ •` beside progress bars drawn in ASCII dashes, where Rich's own guess and markitai's rule disagreed): rounded panels and solid bars where the marks are Unicode, ASCII where they are ASCII.
- **`markitai serve` sign-in URLs are printed whole**: at 80 columns the LAN URL wrapped inside its access token, and the copied link did not sign in.
- **A missing API key is named, and nothing is sent without one**: with `DEEPSEEK_API_KEY` unset, `--llm` on `deepseek/deepseek-flash` sent the request anyway, printed DeepSeek's "Authentication Fails (governor)" four times without naming the variable, and still reported the file `completed`. Before converting, markitai now checks each model's key: its `api_key` (literal or `env:`) or the provider's variable, including the ones LiteLLM also reads (`GOOGLE_API_KEY`, `OR_API_KEY`, `ANTHROPIC_AUTH_TOKEN`). A model without one is left out of the pool, with one warning naming the variable to set. When no model has a key, the run stops with that one line and exit `1` (`--json`: `ok: false`), and the Python API and MCP raise `NoModelConfiguredError`. A DeepSeek or OpenRouter model with its own `api_base` (a local server, a gateway) is never held back. `markitai doctor` applies the same check.
- **A refused API key is reported once, with the variable to fix**: a provider's HTTP 401 now prints one line per item, for example `deepseek/deepseek-flash rejected the API key in DEEPSEEK_API_KEY with HTTP 401; set a valid one with: export DEEPSEEK_API_KEY=your_key. Provider message: …`, instead of the same error from every layer. It is not retried in other structured modes, and once every model's key has been refused the rest of the run sends nothing. A `.urls` batch used to report "No deployments available" for later URLs after about 9 s of retries. Batch and single-file report files now list each item's `warnings`, as `--json` does, so an item that kept its unenhanced output no longer looks like a clean success.
- **Install hints for a missing extra keep the install**: `uv tool install "markitai[legacy]" --force` (shown by `doctor` and by errors that need an extra) replaced the tool with exactly that, dropping every extra `setup.sh` had installed and swapping an install from a checkout for the PyPI release. The command now lists the extras already installed plus the missing one, from the same source (`uv tool install "markitai[browser,legacy,ocr,serve] @ /path/to/markitai" --force`), read from uv's own record of the install. When several extras are missing, as after `setup.sh` or `setup.ps1` without a terminal (which installs only the core), `doctor` prints one command that adds them all instead of one reinstall per extra, and the setup summary says how to install everything without a terminal (`MARKITAI_INSTALL_OPTIONAL=1`, then run setup again).
- **Windows on Arm installs on an x64 Python**: markitai cannot install on a native ARM64 Python: pymupdf-layout, which every PDF conversion needs, has no ARM64 build at all, and the LLM library needs fastuuid and tiktoken, which would have to be compiled with Rust. `setup.ps1` used whatever Python uv found first, so a machine with python.org's ARM64 Python ended with `pymupdf-layout ... has no wheels with a matching platform tag (e.g., win_arm64)`. It now picks an x64 CPython 3.11–3.13 on ARM64 Windows, installs CPython 3.13 x64 with uv when there is none, and says why in one line. Install hints from `doctor` and from errors add `--python cpython-3.13-windows-x86_64` there, so a reinstall stays on it, and the getting-started guide says what to run with uv directly. markitai runs emulated on these machines, as uv's own default Python does.
- **No WMI queries on every run on Windows**: with Python 3.12 and later, `platform.system()` asks Windows Management Instrumentation for the OS version and the CPU, and markitai called it on every run (sizing its converter pool, looking up the system proxy before a fetch). Each query is a call into another process, and in a session that may not query WMI, such as an SSH logon, each one waits about 5 seconds before failing. markitai now reads the OS from `sys.platform`.
- **Setup installs markitai once, and the first run after it is not the slow one**: on Windows 11 on Arm (x64 Python under emulation) the owner's `setup.ps1` took over ten minutes and the first `markitai doctor` after it minutes. Setup installed markitai, asked the new install which extras to add (`markitai doctor --suggest-extras`, the first run of an install) and installed it again with `--force`, which rebuilt all 137 packages; both times uv compiled every file of the environment to bytecode (`UV_COMPILE_BYTECODE`, about 13,400 files, most of which markitai never imports, each new file scanned by Windows Defender). Now `setup.sh` and `setup.ps1` ask every question first (Web UI, OCR, the Playwright browser, the Claude Code and Copilot CLIs) and install markitai once with every extra the answers add; an existing install is updated in place, so uv adds and removes only what changed, and an unpinned PyPI install takes the newest release as `uv tool upgrade` did. Right after the install, `python -m markitai.warmup` compiles what markitai's code imports (about 6,300 files, in four background processes below normal priority) while setup goes on, and launches Chromium once after its download (the slow first launch while antivirus scans it); setup waits for it before the summary. A `UV_COMPILE_BYTECODE` you set still applies. Every step shows a spinner with its elapsed time and the step's latest line (uv's `Downloading …`), ends with its duration, and setup ends with `Setup took …`; `MARKITAI_SETUP_TIMINGS=1` lists every step, with uv's own resolve, download and install times. Before, the first run compiled every module it imported: on an ARM64 test machine the first URL conversion took 44 s against 4.6 s for the next.
- **`markitai doctor` and `markitai --version` start fast**: doctor imported LiteLLM (about 2,400 modules, 8 s per run on the Windows machine) only to tell whether each configured model reads images; it now reads LiteLLM's model table file for that (the same answer for all 6,978 names of LiteLLM 1.104.2's table). Its checks run at the same time, the Claude Code sign-in check (which starts the `claude` CLI) included, and a terminal shows which are still running; a Chromium that launched is remembered for a week for the same Chromium, Playwright and Python instead of being launched on every run (`--fix` always launches). `markitai --version` answers before the CLI loads (it imports 50 modules instead of 430). `doctor --timings`, or `MARKITAI_TIMINGS=1` for any command, prints where the time went. Measured on Linux over 235 pages: 6.0 s to 3.2 s, the Wikipedia page 0.40 s to 0.20 s. The Markdown is byte-for-byte the same.

The first element marked as the abstract (class `abstract`, `itemprop="abstract"`, `role="doc-abstract"`) stays when the block around it is removed; author bios and the rest of the block still go.

Python's resource tracker then printed `UserWarning: resource_tracker: There appear to be 3 leaked semaphore objects to clean up at shutdown` after the summary, sometimes after the shell prompt had returned, which looked like truncated output (in about 1 run in 7 of an 11-file batch). The CLI, `markitai mcp` and `markitai serve` (stopped with Ctrl-C or SIGTERM) now wait for the pool to release them before exiting. Windows was not affected.

- **`llm.max_requests_per_document` caps the whole document**: a document's text enhancement and its image analysis each had their own budget, and a stage that finished gave its requests back, so with a cap of 3 `sample.pptx --llm --alt --desc` made 6 requests. - **An unknown model price is no longer reported as free**: a model LiteLLM has no price for, or one the config only describes with `model_info` (which registers it without a price), was reported as `cost_usd: 0.0`, as if it were free. Its requests are now counted as `unpriced_requests` in `llm_usage` (in `--json`, the report files and the Python API's `ConversionUsage.by_model`), the batch summary says "cost unknown", and a warning names the model once per run. `cost_usd` stays a number and covers only the priced requests. Live requests to OpenAI's reasoning models now ask for a JSON schema response (`response_format`) instead of a function call; `--llm-batch` keeps the function call, with reasoning off.
- **Subscription cost estimates name the right model**: the equivalent-API cost of a Copilot or ChatGPT request is found by matching its model name against LiteLLM's table, and a number that appears twice in the name could match a name where it appears once, so `copilot/claude-haiku-5.5` was priced as `claude-haiku-4-5`, at ten times its rate.

The same could happen to a CLI or MCP run that logged a warning on those loggers while LiteLLM loaded. markitai now keeps those filters out of the way until the import is done. Opening **Settings → Models** within a second or so of starting `serve` broke it the same way: the provider list imported a part of LiteLLM on another thread while the background import was still running, the two imports deadlocked and Python failed one of them, so the picker offered no providers and every model test and LLM conversion failed with "partially initialized module 'litellm'" until a restart. LiteLLM itself is now imported first there.

On Windows they were keyed `sub\a.txt`, so a state written there could not be resumed on Linux or macOS, and progress saved on those systems since the last full save was lost when resuming on Windows. On Windows, a state written by an earlier version still resumes.

- **ODS tables keep their gaps**: a run of empty cells (`1, <empty ×2>, 4`) no longer collapses to one, which moved later values into the wrong column; runs of empty rows are kept too.
- **PDF tables without ruling lines stay tables**: a table drawn without borders that the PDF extraction did not recognise (a browser's default table style, its cells a few points apart) came out as one line of words, `Language Year Typing Primary Use Python 1991 ...`. markitai now reads the columns from the white gaps every row shares and writes a Markdown table, but only for a paragraph that is exactly such a table's words; prose, lists, text in columns, aligned code and monospaced text are left as they are. On 39 PDFs (papers, reports, forms, an RFC, Japanese statistics) it changed the two flattened tables and nothing else, at about 3 ms per page.
- **ChatGPT provider**: a rate limit (429) or server error (5xx) that outlasts the retries now fails only that request instead of skipping the rest of the document, and a truncated or failed streamed answer is reported as such instead of being accepted and cached as complete.

Terminal output is unchanged.

From the web API, `env:` references are limited to the provider key variables (`env:OPENAI_API_KEY`, …) with the provider's default endpoint, plus key and `api_base` pairs already in the config file. A saved key or `env:` reference stays bound to its saved `api_base`, also when a model or provider is edited (422 otherwise; send the key itself to use another endpoint).
- **LLM errors no longer show your API key or document text**: a provider error that repeats the request was printed as given, so an HTTP 401 naming the key showed the full key, and an HTTP 400 quoting the request showed the document's text, on stderr, in log files, in `--json` output, in batch report and state files, and in `serve` and MCP errors. The configured keys, provider keys in the environment and anything shaped like a key or token (`sk-…`, `Bearer …`) are now replaced with `[REDACTED]`, quotations longer than 40 characters with `'…'`, and a message that repeats the request is withheld. The error type, the HTTP status and the rest of the provider's message are kept. `--llm-batch` error lines are cleaned the same way.
- **Crash tracebacks no longer show variable values**: an unexpected error logged with its traceback (the conversion step's DEBUG log, `serve` job and request crashes, errors from libraries such as LiteLLM and Uvicorn) printed every frame's local variables, which can hold the API key and the document's text, on stderr and in the log file. Every log output of the CLI, `serve` and `markitai-mcp` now prints the traceback without the values, and keys and URL credentials in the exception's own message are replaced with `[REDACTED]`.
- **`serve` request log**: the access token the web workspace adds to event-stream, file and archive URLs (`?token=`) is masked in the console and log file.
- **URL fetching**: a response larger than 500 MB (the local-file limit) fails the fetch instead of being read into memory without bound; an over-limit `Content-Length` fails before the body is read.
- **Credentials in URLs**: a URL with a `user:password@` part no longer writes it into screenshot filenames or into `~/.markitai/learned_spa_domains.json`.
- **URL screenshots on Windows**: a long URL's screenshot name runs to 200 characters, so under an ordinary output folder the path passed Windows' 260-character limit, and without long-path support (off by default) the screenshot was lost. On Windows such a name is now shortened to fit, keeping its start plus a short hash so different URLs still get different files.
- **Web extraction sanitizer**: `javascript:` links in inline SVG (`xlink:href`), in `srcset`, `poster` and `data`, or split by tabs, newlines and control characters (`java&#9;script:`) are removed instead of reaching the Markdown.

- **PDF hidden text**: `security.pdf_sanitize = "remove"` no longer deletes visible text that a hidden span repeats (a hidden `e` used to remove every `e` on the page), white text on a dark background is no longer reported as hidden, and `--ocr --llm` checks the text it sends to the model like the other paths.

It used to delete a short line from the body wherever it appeared, strip lines found on only half the pages, and miss running headers. Pages and slides get a second round, so a three-line footer such as PowerPoint's (date, text, slide number) still comes off whole. `markitai.utils.text.clean_ppt_headers_footers` is replaced by `markitai.utils.page_chrome.strip_repeated_marker_lines`.

- **Converters**: `.txt`/`.md`, HTML, XML, reStructuredText, Org and LaTeX files in a legacy encoding (Latin-1, GBK, a `<meta charset>` page) read correctly instead of failing or turning into replacement characters; a CSV whose encoding cannot be detected keeps its rows instead of becoming `None`; RTF with embedded binary data (`\bin`) converts; LaTeX `\href{url}{text}` becomes a link; two horizontal rules in the body are no longer taken for frontmatter when picking the title; and an image description with backslashes (`C:\temp`) is written as given.

The kept page is the page as the browser drew it, before the clean-up for text extraction: style rules a script inserted (CSS-in-JS) are written into the copy, scripts are left out. The cost is the page copy, a few kB to a few hundred kB (an X post: 27 kB beside its 66 kB screenshot).
- **A web page from an earlier session is framed at its own address.** After `markitai serve` restarted, Compare framed a URL item's kept page with `<base href="None">`, so its style sheets, pictures and links resolved against the workbench instead of the site and the page showed unstyled with broken pictures. The base is the item's URL again.
- **On Windows a URL's screenshot comment uses `/`.** The Markdown referenced its screenshots as `.markitai\screenshots\…`, so Markdown viewers on other systems did not find them, and `markitai serve` did not count them as the item's: Compare had no screenshot pages, the result did not list them and deleting the item left them behind. References are written with `/` everywhere, and jobs written before are read either way.
- **No table gets a second delimiter row.** A model rewriting a table sometimes repeated its `| --- | --- |` row, which showed as a data row of dashes in the `.llm.md`; the shared Markdown cleanup now drops a delimiter row a table already has (outside code blocks).
- **A misnamed file says what it is.** An `.epub` that was really a gzip-compressed PostScript file failed with "Malformed EPUB: File is not a zip file"; it now says "This is not an EPUB file: it holds gzip-compressed data, while an EPUB is a ZIP package. Check the file (it may be misnamed or still compressed)." OpenDocument files say the same.
- **CJK text from Chrome's PDFs uses the right characters.** Chrome's "Save as PDF" names some CJK glyphs by radical code points in the PDF's text layer, so the Markdown read `使⽤` and `右下⻆` (U+2F64, U+2EC6) for 使用 and 右下角, which look alike but do not search, sort or match. PDF output (base and LLM, and the text the LLM paths read) now folds Kangxi radicals (U+2F00–U+2FDF) and the CJK radical supplement forms that stand for one ideograph to those ideographs, with the workbench's mapping (NFKC, then 28 supplement forms NFKC leaves alone); component shapes such as ⺁ stay.
- **A line break inside a table cell no longer breaks the table**: a cell holding a line break (a newline in an XLSX, XLS or ODS cell or in a quoted CSV field, a second paragraph or a `<br>` in a DOCX, HTML, EPUB, PPTX or ODT cell, a soft line break in a PPTX cell, or a U+2028/U+2029 line or paragraph separator, vertical tab or NEL in any cell) is written as `<br>`, so the row stays one line. CSV wrote the newline into the row, which split it in two; U+2028 ended the table in renderers that take it for a line end; DOCX, HTML and PPTX joined the lines with a space. Runs of breaks become one `<br>`, breaks at the start or end of a cell are dropped, a `|` in a CSV, DOCX, HTML or PPTX cell is escaped (it added a column), and `<br>` written as text in a cell stays text (`&lt;br&gt;`). A separator left inside a row by a model's answer (the `.llm.md`) or any other path is written as `<br>` by the shared Markdown cleanup.

### Security

- **The server's own API keys no longer go to an address a settings caller picks.** A model or connection saved through the `markitai serve` settings page (or tested there) without a key, but with an address, made LiteLLM read the server's key variable for that provider (`OPENAI_API_KEY`, `GROQ_API_KEY`, `LM_STUDIO_API_KEY`, ...) and send it to that address: anyone holding the access token could have the server's key sent to a host of their own, which the rule against `env:` references aimed at a caller's host was meant to prevent. Such an entry now stores the placeholder key `markitai-no-key`, which no server takes as a credential (a server that checks no key, such as LM Studio, vLLM or llama.cpp, works with it, and a keyless OpenAI-compatible endpoint now works at all; it is shown as having no key), and a connection test at an address the caller names uses it too. A connection with a key can no longer be turned into one without a key at another address (HTTP 422). Entries written by hand in the config file are unchanged: one without `api_key` still uses the environment's key, wherever its `api_base` points.
- **The server's Google, watsonx and GigaChat logins no longer go to an address a settings caller picks.** LiteLLM signs Vertex AI requests with the server's own Google credentials (application default credentials, `gcloud` login or `GOOGLE_APPLICATION_CREDENTIALS`), watsonx ones with `WATSONX_TOKEN` and GigaChat ones with `GIGACHAT_ACCESS_TOKEN`, whatever key the entry has, and sends them to the entry's address: a Vertex AI model saved or tested through the `markitai serve` settings page with an address of the caller's choosing (also a bare name such as `gemini-2.5-pro`, which LiteLLM routes to Vertex AI, or one saved under another connection's address) carried the server's Google access token there, in tests and in conversions. The settings page now refuses such a model with an address (422 `invalid_settings_request`, shown in English, Chinese and Japanese), and **Add models** offers Vertex AI no address field, with a short note that it uses the server's Google login at Vertex AI's own endpoint, and a saved Vertex AI connection offers no key; without one it keeps using the server's login at the provider's own endpoint, and an address written in the config file by hand is still used. Amazon Bedrock is unaffected: with an address and no key it sends the `markitai-no-key` placeholder as its key, never the server's AWS credentials.

- **Python 3.14 support**: `requires-python` narrows to `>=3.11,<3.14` across the package and installers, and the CI/publish matrices no longer test 3.14. The platform-conditional ONNX Runtime constraint that existed only to keep 3.14 resolvable is gone with it
- Excel COM automation (Windows) and Excel AppleScript automation (macOS), together with the `.xls` entries in the batch pre-conversion and heavy-task paths, since `.xls` no longer needs them

### Fixed

- **The cross-session LLM cache never actually hit**: the persistent cache's reads and writes disagreed on the cache key's model column, so no run ever saw a previous run's results, and every rerun of an already-processed document paid the full LLM cost again. Reads and writes now agree (locked by a regression test), and reprocessing an unchanged document is near-instant and free
- **macOS `.doc`/`.ppt` conversion via Microsoft Office was broken end to end**: Word's and PowerPoint's AppleScript `open` returns nothing, so the script's document binding was never established. The first reference died, the error handler's own reference to the same variable masked the real error behind an inscrutable "variable openedItem is not defined", the document was never closed, and the stranded zombie documents degraded the app further with every retry. The script now binds the document by its unique staged name, closes it under both its pre- and post-save names, and always propagates the original error. Excel's "Parameter error -50" had the same root and is fixed the same way (moot for `.xls` now, see Removed, but the fix also covers the PPTX-to-PDF export path)
- **macOS: `.doc`/`.ppt` conversion failing on an Office app's first scripted launch after an Office update** ("the document never registered" / PowerPoint error -9074). In that state the app silently drops Word's parametered `open` request while answering everything else; Word's script now retries with a plain `open` mid-poll (verified to penetrate and heal the state) and logs the recovery. Error messages for the stall and for -9074 now carry the verified remedy (open the app manually once so it finishes first-run setup) instead of the misleading "app stuck or overloaded, quit and retry"
- **Truncated or degenerate LLM output no longer poisons the cache**: screenshot extraction and URL enhancement now reject length-truncated responses like every other call site, and URL enhancement no longer caches output whose degenerate tail had to be cut
- **`markitai -I` no longer crashes with a raw traceback when a config file is invalid**: the interactive wizard now reports the same actionable message as every other command
- **Directory-batch reports no longer drop screenshot counts for URL entries**
- **The defuddle HTTP client now rebuilds when proxy or timeout settings change** (it previously kept the first client for the whole process, like jina always did correctly)
- **Disabled models (`weight: 0`) no longer affect cache scoping**: disabling a model stops serving its old cached results, and adding or removing a disabled entry no longer invalidates the pool's cache
- **Copilot authentication status reads correctly with current Copilot CLIs**: newer CLI versions write JSONC-style comments and renamed the login key, which made `doctor` and `auth copilot status` report a parse error as "not logged in". Both formats are now accepted, an unparseable config reports as indeterminate rather than unauthenticated, and a login the CLI itself reports as successful is never vetoed by the follow-up config read
