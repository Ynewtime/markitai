# Changelog

## [1.3.0]

### Added
- `markitai serve` records how a web page looked when it was captured: the original descriptor's `capture` says, for the kept page and for its screenshots, whether each showed the content (a picture or a player with a short caption counts), a blank page (or only a request for JavaScript) or a verification, captcha or login page instead (`{state, text_length, title, reason}`), and `GET …/original/blocks` gives the boxes of the page's blocks where the browser drew them when it took the screenshots (`blocks` in the descriptor). A page the browser loads in a service job also gets compare screenshots when none were asked for (JPEG tiles beside the job, at most 20, never part of the result or sent to a model). Workbench contract v1.14.
- The workbench's Compare links the Markdown with a web page's screenshot too: hovering a block outlines it on the screenshot (and back), from the boxes the server recorded.
- `markitai serve` access levels and Edit config. The server token is the admin's; an admin creates labelled user tokens in the workbench (`GET`/`POST /api/access-tokens`, `DELETE /api/access-tokens/{id}`; at most 50, each shown once and kept only as its SHA-256 in `MARKITAI_HOME/serve/access.json`, so they survive restarts and token regeneration). A user token reaches everything but the settings and the token routes (403 `settings_forbidden`) and sees only the jobs it created (any other is 404 `job_not_found`, in history, archives, tickets and deletions too); revoking one stops its requests, download tickets and event streams at once. `GET`/`PUT /api/settings/config` shows the configuration file's own text with every secret masked and saves the edited text exactly as written (the workbench sends it back with the file's own line endings, so on Windows a CRLF file keeps CRLF, Review shows only real changes and unchanged lines stay byte-identical; a masked value kept in place is put back as the stored secret; a stale revision is 409, an invalid file 422 `invalid_config`), applying models and providers at once and reporting `restart_required` for the rest. Capabilities report `access` (`role`, `label`), `features.user_tokens` and `features.config_edit`.
- `POST /api/history/delete` deletes several saved jobs and items in one request (`{jobs, items}`, 1 to 1,000 entries), each exactly as its single route would, and answers every entry's outcome in order (`features.batch_delete`).
- The workbench's Conversions list deletes several conversions at once: a box at the left of every row and submission header, Space/Shift/Ctrl+A/Escape/Delete on the keyboard, a bar with the count, Select all, Clear and Delete (asked first, saying the files go too), Select mode on phones; on a backend without the batch route it deletes one by one, four at a time, and names what failed. Settings has Edit config (admin): the configuration file as text with secrets masked, checked as JSON while typed, a diff before saving, saved against the revision it was opened at.
- `markitai serve`'s `GET …/original/pages/{n}/text` also lists where the page's pictures are drawn (`images`, boxes in the same frame as its lines), so the workbench's Compare can outline a PDF's picture on its page.
- `markitai serve`: `GET /api/jobs/{job_id}/items/{item_id}/archive` zips one item's result files and its kept original; `GET …/original/view` sends a kept web page for a sandboxed frame (one `<base>` inserted, a policy that allows no script, form or remote load, framed only by the service's own pages; opened with a download ticket); `POST /api/access-token/regenerate` replaces the access token, revoking the old one, its download tickets and its open event streams. Capabilities report `features.item_archive` and `features.token_regenerate`; the static pages allow `frame-src 'self'`; a URL item's screenshots are also offered beside its kept page.

- HEIF/HEIC images decode on Windows and Linux with a built-in pure-Rust decoder (heifer), for conversion, vision models and local OCR, as on macOS; they were an unsupported error before.
- AVIF images decode on Windows and Linux with rav1d, the Rust port of the dav1d AV1 decoder (vendored, without assembly), for conversion, embedded images, vision models and local OCR, as on macOS; they were an unsupported error before. Grids, alpha planes, 10/12-bit and the crop, rotation and mirror properties are read; overlays are an explicit unsupported error, and a decoder failure fails only that image. One file decodes at most 96 million pixels and 2,050 AV1 items in all, so a 3 KB grid that names one 30-megapixel tile 1,024 times fails in about a second instead of decoding for minutes. The decoder adds about 1.2 MB to the release CLI.
- `markitai serve` shows an item's original beside its Markdown: `GET /api/jobs/{job_id}/items/{item_id}/original` describes what is kept (an uploaded PDF, image, HTML or text file, a URL item's page as converted from HTML, or else the page screenshots) with its page boxes, `…/original/file` downloads it (HTML and SVG as plain text, sandboxed), `…/original/pages/{n}` draws a PDF page or scales an image (TIFF and HEIC/HEIF as PNG), and `…/original/pages/{n}/text` gives a PDF page's text lines with their boxes. At most two pages are drawn at a time (429 `render_busy`).
- Service jobs take an optional `label`, returned in snapshots and history; `GET /api/history?include=items` returns each job's items with its summary; `…/result?max_bytes=` returns the start of a long result, cut at a line, with `truncated` and `markdown_bytes`; items report `models` and `source_size`; capabilities report `implementation`, `docs_url`, `source_url` and `features`.
- The workbench reads an uploaded `.urls` file as a URL list: each entry becomes a URL item (comments and blank lines skipped, an entry that names its output keeps that name), instead of failing as an unsupported document. A batch — a folder, several chosen files, a drop that reached into a folder, or a `.urls` list — now waits for Convert with one staged line naming it, so its options can be chosen first; a single file still starts at once. Such a submission is one header row in the conversions list, named after the folder or list, with its items under it.
- `--help` ends with the build identity of the binary: its version, the commit it came from (marked `(local changes)` when the worktree differed, `unknown` outside a checkout), the target and profile, and the time the build ran in the reader's own time zone with its UTC offset. `SOURCE_DATE_EPOCH` fixes that time for reproducible builds; `-h` and the one-line `--version` are unchanged.
- Native Rust conversion core, standalone CLI, and in-process Python, Node.js and Go bindings. CLI packages need no Python, Node.js or Go runtime.
- Windows x64/ARM64 ZIP and macOS/Linux CLI archives with command aliases, dependency licenses and offline Markdown guides, including `llms.txt` and `llms-full.txt`. Optional static Go packages support macOS arm64 and Linux x86-64; Windows Go/cgo distribution remains unvalidated.
- Embedded `markitai serve` workbench with Chinese, English and Japanese, light/dark themes, responsive layouts, file/folder/URL submission, upload progress and cancellation, result previews, base/enhanced differences, history, retries and downloads.
- The workbench's Rendered view draws the inline SVG charts and diagrams a converted web page keeps as markup, instead of an empty block. Each drawing is sanitized and kept to itself: drawing properties from `style` become attributes, `id`s get a prefix of their drawing, `href`, `xlink:href` and `url()` resolve only to elements of the same drawing, and images, `foreignObject`, style sheets, scripts, animations and `use` of other documents are removed, so a drawing loads, runs and reaches nothing; unpainted labels take the text colour and read in dark mode.
- The workbench's Preview shows a document's contents when it has four or more headings: its top three heading levels beside the document on a wide window, marking the section being read as it scrolls, and a sheet from a round button on a phone or a narrow window. A button beside Base | LLM hides or shows them, remembered in this browser.
- REST conversion jobs, event streams and OpenAPI documentation; native stdio MCP conversion tools and bounded batch jobs through `markitai mcp` or `markitai-mcp`.
- Native RST, Org, TeX and Outlook MSG readers, notebook outputs, Numbers tables and directory packages, MIME-aware email attachments, and Office metadata extraction.
- Local image/PDF OCR with macOS Vision or portable PaddleOCR, with explicit language selection and English/Chinese/Japanese/Korean default routing. Portable models install separately with integrity checks; `doctor` inspects them and `doctor --fix` repairs them.
- PDF screenshots and scanned-page OCR on Windows/Linux through the in-process hayro renderer; macOS uses CoreGraphics by default. Optional LibreOffice export adds Office screenshots and OCR. Multi-page TIFF, SVG vision previews and macOS HEIF/AVIF decoding are also supported.
- PDF hidden-text policy `security.pdf_sanitize` with `off`, `warn` and `remove` modes. Supported suspicious text can be excluded from the extracted body; original assets remain intact, and incomplete inspection is reported.
- Optional isolated Chromium fetching, screenshots, origin-scoped Basic/Digest authentication and authenticated PDF downloads; explicit browser installation through `doctor --fix`, reusable isolated sessions and operating-system manual proxy discovery.
- Cloudflare URL/file conversion and Jina/Defuddle fetch fallbacks, subject to remote-processing consent and local-only policies. The workbench requests consent per operation; privacy notices identify off-device image and URL processing.
- Weighted model routing, fallback groups, retries, concurrency and request budgets, custom prompts, structured document metadata and image descriptions. Persistent fetch/LLM caches and identical-request coalescing avoid repeated work.
- Additional OpenAI-compatible providers, model discovery and connection probes, plus optional Copilot, Claude and ChatGPT subscription conversion through supported official runtimes. Subscription authentication status and delegated login are available.
- The other OpenAI-compatible prefixes Python markitai reaches through LiteLLM are routed too (69 more, from `ai21/` and `volcengine/` to `cohere/`, `huggingface/`, `bedrock_mantle/`, `cloudflare/`, `databricks/`, `llamafile/` and `docker_model_runner/`), with LiteLLM's model naming and key variables. Each base URL was checked against the provider's documentation on 2026-10-11, and where a provider documents a newer host or key name than LiteLLM, the documented one is used or read first. `huggingface/<provider>/<org>/<model>` asks the router for that provider, `bedrock_mantle/<region>/<model>` and the AWS region variables choose Bedrock's region, and Workers AI takes `CLOUDFLARE_ACCOUNT_ID`. Prefixes of services that ended (GitHub Models, Meta's Llama API, Lambda and Hyperbolic inference, and others) are refused with the reason instead of a generic error.
- `bedrock/<model>` and `vertex_ai/<model>` work without their SDKs, as Python markitai's do through LiteLLM. Bedrock goes through the Converse API for every chat model (foundation models, inference profiles, ARNs), with a Bedrock API key or AWS keys signed with Signature Version 4, found in the AWS SDKs' order: the deployment's `api_key`, `AWS_BEARER_TOKEN_BEDROCK`, the AWS key variables and `~/.aws` profiles (static keys, `credential_process`, and SSO or role profiles through the AWS CLI). Vertex AI serves Gemini and Model Garden models through its OpenAI-compatible endpoint and Claude through `rawPredict`, with access tokens minted from a service account, user credentials or gcloud's application default credentials, or taken from the gcloud CLI. Both were checked offline (the AWS signing test suite, curl's own signer, local token endpoints); their costs are not in the pricing catalog yet.
- OpenAI text Batch submission, collection and restart continuation with private request records, reconciliation and output ownership checks. Observed usage, unknown pricing and failed-attempt costs remain distinguishable.
- `--llm-batch` also submits to Anthropic Message Batches for an `anthropic/<model>` deployment, as Python markitai does: the same submit, wait, `--llm-batch-collect`, `--resume` and `llm.on_failure` handling, with the live request's structured mode and batch-rate costs. The requests travel inline in the one create call, after checking them against their saved digest; each custom ID carries the submission nonce, so an uncertain creation is reconciled by opening the results of ended batches of the same size, never by creating again. Errored, canceled and expired requests are item failures without usage, as Anthropic does not bill them.
- A batch Python markitai 1.2.x submitted and left pending is collected after upgrading: `--llm-batch-collect ID -o DIR` (or `--llm-batch --resume -o DIR` for the only one) reads Python's `.markitai/batch-<ID>/` state without changing it, turns it into a native job for the same OpenAI or Anthropic model, and publishes the `.llm.md` files from the answers Python paid for. Python's image and page/slide placeholders are recomputed with its own rules (checked against its saved requests) and must all come back once; `--alt` captions and `--desc` descriptions of that run are applied as Python would. A normal `--llm-batch` run into such a directory names the pending batch and its collection command.
- Collecting a provider batch prints each document's warnings (a base kept after a failed answer, an image analysis that failed), as Python does; the run report still leaves warnings out.
- CLI reports, optional history, resumable directory/URL-list batches, controlled interruption, publication locks and recovery receipts. Shared assets and stdout image assets persist under isolated Markitai state.
- Chinese/English CLI help and guided conversion, configuration initialization/editing/validation, capability diagnostics and private rotating logs. Windows supports native console handling, subscription command shims, recovery and process-tree cleanup.
- `markitai serve` serves an item's own extracted images for display: `GET /api/jobs/{job_id}/items/{item_id}/assets/{relpath}` sends only a PNG, JPEG, GIF, WebP or AVIF that the item's result lists, inline and sandboxed, with an `ETag` (a matching `If-None-Match` is 304); anything else, another item's image or a path leaving the job is 404 `file_not_found`. Capabilities announce `features.item_assets`. The workbench reads preview images through it and now shows the pictures in the inspector's "Start of the result" too, where every picture used to read "[Image: preview unavailable]"; an image reference whose folder does not match (an e-book's own `../Images/x.png`, a model's `assets/x.png`) resolves by file name to the item's one listed image of that name.

- Local OCR with the portable engine (Windows, Linux) is about 18% faster on single files and 13% on a batch of scans: tract's operators (`tract-core`) are now optimized for speed within a size budget (`opt-level = "s"`) instead of minimum size. The Linux arm64 release CLI grows by 4.7 MB (38.7 to 43.4 MB); full speed optimization (`opt-level = 3`) would add 2.3 MB more for less than one point more. Recognized text is unchanged.
- Every line the CLI prints follows one terminal style, the one Python markitai 1.2.1 uses, so both look the same. A mark says what a line is (`✓` success, `!` warning, `✗` error, `→` the next step or an action in progress, `•` a fact, `○` skipped on purpose, `?` a prompt, `◆` the title) and its colour only repeats that: green only for success, yellow only for warnings, red only for errors, cyan for the title mark, prompts and commands to copy, gray for details, bold uncoloured section headers; no magenta, blue or bright colours, so light and dark themes read the same. `doctor` now shows a title, the version and configuration, Optional Capabilities, LLM and Authentication sections, the remedies with each command on its own line, and a closing verdict (a green `✓ Ready. Not available (optional): …` when only optional checks are missing, as Python markitai prints it, `✗ Not ready: fix … first` when the configuration needs one). Stderr diagnostics read `  ! …` and `  ✗ …` instead of `Warning:` and `Error:` (the file log keeps those labels for searching), the batch summary starts with its verdict and ends with the output directory, `init`, `-I`, `config edit`, `cache`, `auth`, usage errors and `--help` use the same marks and colours, and `serve` prints each address to open on a line of its own so it copies whole. On a terminal long lines wrap under their text; piped output keeps one line per message. `NO_COLOR` turns colour off (the marks stay), `FORCE_COLOR` turns it on for a pipe, `TERM=dumb` gets neither colour nor wrapping, and output that cannot draw the marks (a Unix locale with another character set than UTF-8, a Windows console that cannot read escape sequences: before Windows 10 version 1511 or with "Use legacy console") uses `+ ! x > - o ? *`; Windows pipes and files stay UTF-8 but carry the Unicode marks only when the console's output code page is UTF-8 (65001), because Windows PowerShell decodes a program's output with that code page (at 437 `✓` reads as `Γ£ô`): other code pages get the ASCII marks, and a process without a console keeps the Unicode ones. The spinner and the status line's ellipsis follow the same choice as the marks. Chinese chosen by the locale falls back to English where the output cannot draw it (`zh_CN.GBK` on Unix, a legacy console without a CJK or UTF-8 code page).
- `markitai serve` keeps history for seven days, as the reference service does: a job is deleted seven days after it finished, at startup and hourly, and is hidden from history, job routes and archives from that moment; running jobs and pending retries are never expired. History was kept until deleted before. Capabilities report `limits.history_retention_days: 7`.

### Fixed
- The workbench's Compare links a web page's blocks in Safari and on slow networks: the frame was linked only at its load event, which waits for every picture of a page that runs no script (lazy loading needs script) and so came late or never, and Safari runs no handler the workbench adds inside such a page; the page is now read as soon as it is parsed and the pointer followed by the page's own hover state. Pictures the Markdown names by a downloaded copy pair with the page's picture between their neighbours. A page kept from the browser keeps its doctype, so its frame no longer lays it out in quirks mode (where hovering found only links), and a picture that could not load stays linked through its placeholder.
- Hovering a block in the workbench's Compare no longer makes the text jump: the outline kept layout containment of the drawn chunk. The contents mark the entry that was clicked (pictures loading below it moved the mark to the next heading), and the heading at the top of the reading area while scrolling.
- An EPUB's metadata goes to the front matter instead of a bold `**Title:** … **Authors:** …` block at the top of the body: `authors` (every creator, a list), `language`, `publisher`, `date` and `description`, as plain text (a Calibre description's escaped HTML read as text, Calibre's `0101-01-01` "no date" left out, a midnight timestamp written as a date), with the keys and values Python markitai 1.2.1 writes; the identifier is no longer written. The enhanced output keeps them, with the model's summary as `description`. Front matter keys follow the reference's order (`title`, `source`, `author`, `authors`, `language`, `publisher`, `date`, `site`, `published`, `canonical_url`, `description`, `tags`, …).
- A document's title is plain text that names it, as in Python markitai 1.2.1. A PDF takes its Info title only when that names the document (a number or id such as `20240315000127` no longer does), else the most prominent visible text of its first three pages (a two-line title joined, raised footnote marks such as `¹` and white-on-white text left out), before the first heading. Every title loses HTML tags (`<sup>`, `<mark>`), entities, footnote marks and private-use glyphs, and a candidate that is a number, a page number or a default name gives way to the next heading, then to the file name.
- A PDF page whose content stream separates its operators with NUL bytes (white space in PDF, as iText writes a page it modified) is read instead of coming out empty with a request for OCR, which lost all its text: on a Chinese form printed by iText, its whole first page, fields, table and declarations alike.
- CJK text in PDFs is no longer set as inline code or fenced code blocks. A FixedPitch flag that the font's widths contradict (Microsoft YaHei as iText describes it) and a width table listing only a CJK face's half-width letters, its ideographs left to `/DW`, no longer make a face monospaced; a face whose own program says it is monospaced stays code.
- CJK lines in PDFs are headings only when they read as one: a sentence (ending in `。`, holding one, or running on past `，`), a `label：value` field set at about the body size, and a line of more than fifteen words (three CJK characters counting as a word) are paragraphs. Items numbered `1．`, `1）`, `1、` or `（1）` are list items, a CJK line stopping short of its column ends its paragraph, a row of fields set far apart is a paragraph of its own, and a CJK line reaching its column's edge mid-sentence continues into the next line however widely the page spaces its lines (clauses at 20 pt leading came out as one paragraph per line).
- A PDF table whose header row sits between two rules drawn as one segment per column, over rows without rules (a schedule's items and amounts), is read as a table with each cell's wrapped lines joined in its row, instead of a row per line or plain lines.
- A PDF page set in a Word-exported CJK subset font is no longer sent to OCR as garbled text: the reader preferred its own remap of the font, which read the prose as nothing and every leader dot as `措`, over a correct ToUnicode CMap, because CJK punctuation counted against a reading and reading nothing did not (page 1 of a public insurance clause, its reading guide and contents). Half-width Latin glyphs of such a font are no longer taken for a code face either.
- A number set large at the top or bottom of a PDF page (a report's `2025` across its cover in 48 pt) is kept instead of being removed as a page number; folios are small.
- PDF text no longer holds U+FFFF where the ToUnicode CMap maps the `.notdef` glyph to `<ffff>`, as iText writes it, and a bare address in bold text no longer takes the closing `**`, or CJK text right after it, into its link.
- A URL item's `source` and `canonical_url` read as IRIs (`https://example.com/posts/应用/` rather than `%E5%BA%94%E7%94%A8`): escapes of non-ASCII characters are decoded, ASCII escapes, the host and characters an IRI may not hold stay encoded, so the value is the same address.

A model written by hand without a key shows in the workbench's Edit as using its provider's key variable, as conversions do.

The conversion could see its killed runtime fail and exit first with status 1 and a failure message while the interrupt was still removing the runtime's workspace; it now leaves the exit to the interrupt, as does Unix for SIGINT, SIGTERM and SIGHUP.
