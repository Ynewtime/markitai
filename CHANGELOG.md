## [2.0.1] - 2026-10-XX

Markitai 2.0.1 is a fix release for 2.0.0. `image.format: webp` writes lossy WebP again, the same files Python markitai 1.2 wrote; a Chinese terminal reads Chinese from every command, `markitai serve` included; Kimi platform keys from either region work, and Kimi Code memberships are a new provider, both behind one Kimi card in the workbench. The workbench says less, opens its conversion options in a dialog, gains a select-all box and shows each conversion's options as its command line, and the Windows setup script keeps the user Path's registry kind. Update the way you installed: run the setup command again, or `uv tool upgrade markitai` / `pip install -U markitai`. A script that reads `markitai serve`'s startup lines should check the startup change under Changed.

### Added

- **Kimi Code** provider, `kimi_code/<model>`, for a Kimi Code membership key (`KIMI_API_KEY`; address `KIMI_CODE_API_BASE` or Kimi Code CLI's `KIMI_CODE_BASE_URL`). In the workbench, Kimi's open platform and Kimi Code are one **Kimi** card in Add models: paste either key and Load models tries the open platform's regions, then Kimi Code's (Kimi Code first for a key in its documented `sk-kimi-` form), only ever at Kimi's documented hosts, fills in the address that accepted it, and lists the models the key may use (`k3.1-pro`, `k3`, `kimi-for-coding`, …); they are saved as `moonshot/…` or `kimi_code/…`. Requests go to Kimi's Anthropic-compatible Messages endpoint, `https://api.kimi.com/coding/v1` (a kimi.ai key: `https://api.kimi.ai/coding/v1`), with markitai's own User-Agent and up to 32,768 output tokens. Kimi offers the membership for interactive use only: when a key turns out to be a membership key, the page says so in one line (batch conversions take an open-platform key).
- Workbench: a conversion's **Details** show **Show request options** under the status line, which opens its options as the equivalent command line (`$ markitai notes.pdf -o output/ --preset rich --keep-base --no-cache`) with a copy button, and the settings no flag sets as chips under it (`image.format webp`, `ocr.lang ja`). Only what differs from markitai's defaults is listed, the server's own configuration included: jobs, items and history entries now record what they converted with (`settings`, contract v1.22; CLI runs recorded with `--record-history` too). Credentials, addresses and prompt text are never recorded. Jobs from before 2.0.1 show the options their request named, and older CLI history entries their short summary. The browser remembers whether the options are open. The start of the result switches between **Rendered** and **Source**, its first 12 lines as written with line numbers and the result's line count (`First 12 of 4,210 lines`; a result reports `markdown_lines`, contract v1.23).
- Workbench: a select-all box starts the Conversions filter row, above the rows' boxes. It checks every conversion the name filter and the tab list, shows a dash while only some are checked, and clears them once all are; screen readers hear a checkbox (checked, not checked or mixed). The selection bar works as before.

### Changed

- `markitai serve`'s startup block follows the terminal's language and style: a title with the address (`◆ Markitai server listening on http://127.0.0.1:3600`, in Chinese `◆ Markitai 服务正在监听 http://…`), then `• Access token: …`, `→ Open in your browser:` with the address on a line of its own, where jobs and history are kept, and how to stop. A script that read `Markitai server listening on …` or `Remote access token: …` should read the title's last word (the address) and the token line's value (64 hexadecimal characters), which every language keeps, or set the token with `MARKITAI_SERVE_TOKEN`.
- **Workbench:** less explanatory text on every page. What a field or heading does sits behind a small (i) beside it (hover, keyboard focus or a tap opens it; screen readers read it as the field's description), the longer rules are in the guides, and hints, notes and errors are shorter, in English, Chinese and Japanese. The "set the key variable on the server" hint is that (i) on every provider's key field instead of a paragraph. Appearance and the phone settings list drop their subtitles, and the Moonshot AI provider is shown as Kimi Platform.
- **Workbench:** the conversion options open in a dialog instead of unfolding under the address box: a sheet from the bottom on a phone (drag its handle down, tap outside or press Esc to close), a dialog near the top elsewhere. Its first page has the preset and one row per group with the current value (Enhance, Images, Output, then under Advanced URL, Files, Pages, Other), in full colour when it differs from the defaults; a row opens its choices in place, each with a short line under it, and they apply at once. The command line (one line that scrolls sideways, Copy at its right) and **Reset to defaults** / **Save as default** stay at the foot, a dot on **Options** shows that the choices differ from the defaults, and an option the server can't offer (LLM without a model, Cloudflare without its setup) is dimmed with its reason.
- **Workbench:** the provider groups in Add models are a menu button showing the current group when there are more than three. On a phone the preset buttons are smaller (28 px, 11 px labels).
- **Workbench:** on a phone, Docs and GitHub are two icons at the right of the top bar instead of rows in the settings list, which now ends with one line: version · commit · build time.
- **Workbench:** Docs (the sidebar's foot, the phone's top bar) and the price link of a cost notice open markitai.dev, in Chinese for a Chinese page (`/zh/`; Japanese pages open the English site, which has no Japanese pages), instead of the English Markdown docs on GitHub. `GET /api/capabilities` now reports `docs_url: "https://markitai.dev/"`; 2.0.0 reported `https://github.com/Ynewtime/markitai/blob/main/docs/index.md`.
- **Workbench:** the properties above a document name every key markitai writes in English, Chinese or Japanese (`word_count`, `domain`, `source_url`, `content_profile`, …) and markitai's own values by name (`social_post` is "Social post"). Rows that repeat another are left out: the final address or canonical link when it is the source, the renderer when it is the fetch method, the domain when it is the source's host; an X post's display name joins its handle. The Markdown file keeps every key. The key column has one fixed, narrower width, and every key and value stays on one line that scrolls sideways inside its own cell. A row whose value does not fit gets a chevron: it, or a tap on the value, opens the row so the value wraps in full, and folds it again. In Details, the facts' label column is as wide as its labels (at most 120 px, 96 px on a phone).

### Fixed

- **WebP:** `image.format: webp` writes lossy WebP at `image.quality` again, as Python markitai 1.2 did, for embedded pictures, standalone images, TIFF pages and PDF/Office page screenshots. Names stay `.webp` and transparency is kept. The encoder is libwebp 1.6.0 with Pillow's settings, so 1.2 and 2.0.1 write the same file from the same pixels. 2.0.0 wrote pictures without transparency below quality 100 as JPEG (`.jpg`, warning `image.webp_as_jpeg`, now gone) and the rest as lossless WebP: an invented 1600×1067 photo at quality 75 was a 198 KB JPEG and is now a 77 KB WebP. Quality 100 is lossy too, as in 1.2. An oversized WebP page screenshot is retried at lower WebP qualities before the 1024-pixel JPEG fallback.
- **Chinese terminal** (`MARKITAI_LANG=zh` or a Chinese system language): no more English lines from `markitai serve` (startup, stopping, the browser warning, runtime warnings), usage errors (unknown option or subcommand, missing or invalid value, removed options), `auth`, the `config edit` editor, configuration validation, URL fetch failures, Provider Batch and `--resume` messages, history and output-ownership errors and MCP session failures. The notes the core printed straight to stderr without a mark (the local OCR model download, ignored `./.env` names, a folder `markitai.json`'s key references, the Anthropic sampling warning) now carry the CLI's marks and language. Technical details in parentheses, data on stdout, JSON, reports and the file log stay as they were.
- **Kimi platform keys from China** (platform.kimi.com, formerly platform.moonshot.cn) work in the workbench. `moonshot/` always went to `https://api.moonshot.ai/v1`, which refuses those keys with HTTP 401 `Invalid Authentication`. When the default address refuses a pasted key or the server's own `MOONSHOT_API_KEY`, Add models now tries `https://api.moonshot.cn/v1` (Kimi Code: its other region) and saves the models with that address; for a pasted key it also fills it into API address. A key that neither Kimi service accepts gets one short sentence saying so (en, zh, ja), and a model request refused at `api.moonshot.ai` or `api.kimi.com` names the other region's `api_base`. In the configuration file a China key still needs `api_base: https://api.moonshot.cn/v1` or `MOONSHOT_API_BASE`, as with 1.2.
- **Model cleanup:** small models such as Claude Haiku 5.5 dropped the protected markers that stood for underline tags and links (`the answer dropped 3 of the 16 markers …`), so every such document paid for a second request. A link now keeps its words in front of the model and hides only its address (`[text](⟦…⟧)`), and attribute-less styling tags (`<u>`, `<b>`, `<i>`, `<em>`, `<strong>`, `<mark>`, `<ins>`, `<small>`) stay as they are, as in Python markitai 1.2. Link addresses are still restored exactly; an answer that takes an address out of its link is not used.
- **Notices:** an answer that could not be used and was requested again with a usable answer is now the short note `A model answer could not be used, so the request was sent again; a later answer was used` (`llm.answer_retried`; the terminal shows it only with `-v`, in its language and, like every note that only explains, with the info mark instead of the warning mark), without the discarded answer's marker codes. The workbench no longer shows it as an English notice with a warning mark: nothing is missing, and the cost counts both requests.
- **Workbench:** the **Setup guide** link for Claude, Copilot and ChatGPT opens markitai.dev in the page's language at the section for the cause (install, sign in, or the new "If it still fails"), instead of English Markdown on GitHub at a heading that did not exist.
- **Workbench:** a failed model list or model test shows under **Provider's message** only the provider's own words (its HTTP status with its message or error code), and under **Connection error** what the network reported. markitai's own sentences, such as "Claude CLI is not signed in" or a timeout, no longer repeat the heading there. A Claude Code login that is not a subscription, and a model the provider does not serve in the server's region, are now said in the notice and the test result.
- **Workbench:** Compare no longer leaves part of a block's outline on screen when the pointer moves to the next block (a list item's right-hand edge with its rounded corners stayed behind).
- **Windows setup:** `setup.ps1` keeps the registry kind of the user Path when it adds or removes its folder. A Path stored as `REG_SZ` was rewritten as `REG_EXPAND_SZ` by the first install and by uninstall (its entries were unchanged). A missing Path is still created as `REG_EXPAND_SZ`, as Windows does.
- **Setup scripts:** with a 1.x `MARKITAI_VERSION` they no longer suggest installing 1.x from PyPI, which has no 1.x release any more: they say to install 1.2.0 from its Git tag and print the command. The PyPI description and the guides now say that on a platform without a wheel pip has nothing to install and leaves an installed 1.x as it is.

## [2.0.0] - 2026-10-24

Markitai 2.0.0 is the first release of the Rust rewrite, and it replaces Python markitai 1.2.0. The commands (`markitai`, `mkai`, `markitai-mcp`), options and configuration stay the same. They now run as one native program: no Python, Node.js or Go runtime is needed. Most documents convert faster, use less memory and come out better.

#### Install or upgrade

- **macOS, Linux:** `curl -fsSL https://markitai.dev/setup.sh | sh`
- **Windows (PowerShell):** `powershell -ExecutionPolicy ByPass -c "irm https://markitai.dev/setup.ps1 | iex"`
- The setup scripts install this machine's release archive for the current user, after checking it against the release's `SHA256SUMS`. Once the new release is in place, they remove a markitai 1.x that `uv tool` installed. Run the same command again to update; add `--uninstall` (Windows: `-Uninstall`) to remove it.
- **With Python:** `uv tool upgrade markitai` or `pip install -U markitai` (Python 3.10 or later). The wheel carries the same program and all three commands.
- **Platforms:** macOS 11+ (Apple silicon, Intel), Linux with glibc 2.28+ (x86-64, ARM64), Windows (x64, ARM64). Each archive is listed in `SHA256SUMS` and has a build attestation (`gh attestation verify <file> --repo Ynewtime/markitai`).
- `~/.markitai` (configuration, `.env`, caches, history) is kept and read as before. A 1.2 configuration file loads.
- To go back to 1.2, see [rolling back](https://github.com/Ynewtime/markitai/blob/v2.0.0/docs/quickstart.md#rolling-back-to-1x).

#### What is new

- **One core everywhere:** the CLI, the `markitai serve` workbench, the MCP server and in-process Python, Node.js and Go bindings.
- **Workbench, redesigned:** in Chinese, English and Japanese. Compare shows the original beside its Markdown, Diff compares base and LLM output, and math and Mermaid diagrams are drawn. History can be converted again. User tokens can keep their own models.
- **PDF:** a text layer is checked before it is trusted. Garbled layers go to OCR, and hidden text is left out (`security.pdf_sanitize`). Each page says where its text came from. CJK, right-to-left text, tables and charts are handled better.
- **Local OCR:** the portable PaddleOCR engine is the default on every system (macOS Vision is opt-in). `markitai doctor --fix` installs the models.
- **Formats:** new readers for RST, Org, TeX, Outlook MSG and Numbers, and HEIC and AVIF decode on every system. Spreadsheets, legacy Office, EPUB and HTML convert better.
- **Output:** `-f json` writes versioned document JSON, and `--text-only` writes an image or PDF as just the text recognised in it.
- **Models:** 95 provider routes, including Bedrock and Vertex AI without their SDKs. `--llm-batch` also works with Anthropic Message Batches. Image answers are cached, and the prices of common models are checked against the providers' pricing pages. A batch that 1.2 left pending is collected after the upgrade.

#### Changes that can break scripts

- Page and slide markers are off by default; `--page-markers` keeps them.
- `markitai serve` asks for its token from the same computer too (`Authorization: Bearer <token>`).
- Remote fetch services are opt-in. To keep 1.2's fallback, set `fetch.remote_consent: always`.
- A usage error exits 2, and `✓ Wrote …` goes to stderr.
- Batch-only options (`--resume`, `-g`, `--max-depth`, `--llm-batch`) stop a run on a single file.
- Extracted pictures are named by their content (`.markitai/assets/<hash>.jpg`). With `image.compress` on (the default), PNG and HEIC pictures become `.jpg`.
- A folder batch skips symbolic links and names them (`output.allow_symlinks: true` follows them).
- ChatGPT subscriptions go through the official Codex CLI: run `markitai auth chatgpt login` once.
- The full list is in [compatibility](https://github.com/Ynewtime/markitai/blob/v2.0.0/docs/compatibility.md#coming-from-python-markitai-12).

#### Removed

- `markitai doctor --timings` and `--suggest-extras`, `MARKITAI_PDF_WORKERS`, `MARKITAI_STATIC_HTTP`, and inline terminal images (`image.stdout_fetch_external`).
- `batch.heavy_task_limit` is accepted with a warning and does nothing; use `-j`.
- Microsoft Office as a page renderer (`office.macos_fallback` is accepted with a warning): only LibreOffice draws Office pages.
- ChatGPT sign-in through LiteLLM's device-code login.
- The Python extras (`markitai[all]`, `[ocr]`, …) are kept as names but add nothing.

#### Known issues

- **macOS 15 with Vision (opt-in):** under the default language, Vision may label Japanese text `zh-Hans` and read it as Chinese. Set `ocr.lang: ja` for Japanese images. The default portable engine is not affected.
- **`image.format: webp` below quality 100:** there is no lossy WebP encoder yet. Pictures without transparency are written as JPEG (`.jpg`, one warning). Pictures with transparency, and anything at quality 100, are written as lossless WebP, which is larger.
- **PyPI has wheels only**, for the six platforms above, and no 1.x any more. On other platforms pip has nothing to install and leaves an installed 1.x as it is. The source archive on this Release builds with Rust 1.92 or later.
- **Builds are not signed or notarized.** macOS Gatekeeper blocks an archive downloaded with a browser ([what to do](https://github.com/Ynewtime/markitai/blob/v2.0.0/docs/quickstart.md#unsigned-builds-on-macos)); the setup script is not affected.

#### About these notes

The detailed notes in the changelog compare 2.0.0 with Python markitai 1.2.0 and with the 2.0 development builds; many entries under Fixed concern only those builds. Where an entry says "Python markitai 1.3.0", it means the Python development line after 1.2.0. That line was never published; 2.0.0 takes its place.

### Added
- The workbench's Convert options offer what the command line already could (contract v1.20, each shown when the server announces it): a `{ } JSON` switch after the Output profiles (`format: "json"` in job options, `features.document_json`) saves each result's document JSON as `<name>.json` beside its Markdown, in its files, its .zip and the command line (`-f json`); while OCR is on and LLM off, a picker after OCR (`Local · Automatic language`) chooses the local OCR language (`ocr_lang`, from the capabilities' `ocr_languages`: automatic, Simplified and Traditional Chinese, Japanese, Korean, Russian, Arabic, Thai, Hindi, Greek, plus a configured `ocr.lang`), replacing the note about the local engine; Advanced gains a Pages row with Page Markers (`page_markers`, `--page-markers`) and OCR Every Page (`ocr_all_pages`, `ocr.per_page_routing: false`). All four are saved defaults too (`output.format`, `ocr.lang`, `ocr.per_page_routing`, `output.page_markers`), and the OCR settings appear in the command line as `--config-json '{"ocr":{…}}'`.
- The workbench's Download in a conversion's window is a split button: it saves the Markdown, and its caret lists Markdown .md, JSON .json, All files .zip and Choose files… (on a phone, in "⋯"); the item menu's JSON entry stays.
- The workbench words two notices Python markitai now sends in each interface language: the first conversion after an install, while the conversion libraries load once, and the first OCR use, while the OCR libraries and models load once.
- PDF with `--ocr`: a text layer the text-only checks trust is also compared with what its glyphs draw, as Python markitai 1.3.0 does. A few stretches of each font's text (two per font per document, four crops a page at most) are drawn from the page and read by the OCR recognizer alone; a page whose fonts disagree is read by OCR instead, with the page source `text layer failed the script check: the layer's text is not what its glyphs draw (font …)` or `the layer reads Latin, the page shows CJK (font …)`. A shifted alphabet (`cqi luvvoccii` for `the committee`) and Latin codes behind CJK glyphs now come out as the text the page shows. A non-embedded CJK font is drawn from its character collection for the check and for the OCR of such a page, not through the map being checked. It costs about 0.1–0.3 s per document under `--ocr` (mostly loading the recognizer once) and nothing without it.
- With an empty `llm.model_list` and no `MODEL`, subscription runtimes signed in on this machine join the automatic model pool before the API keys, as in Python markitai: Claude Code (`claude-agent/haiku`), Copilot (`copilot/auto`, letting Copilot choose) and ChatGPT through Codex (the lightest current model Codex lists, `gpt-6-luna` today). Each runtime is asked for its own sign-in status once per process; a run that spreads documents over several detected providers says so once. `markitai init` offers the same models (leaving out the Anthropic key's model when Claude Code serves Claude Haiku on a subscription) and tells how to sign in to an installed runtime that is not signed in.
- `markitai doctor` lists provider keys that are set but used by no active model (`Not used: OPENAI_API_KEY (set, but no model in llm.model_list uses it)`; `unused_api_keys` in `--json`), as Python markitai does.
- Image analysis answers (`--alt`/`--desc`) are cached in `cache.db` like document answers, as Python markitai caches them, so a re-run sends nothing and costs nothing for pictures it has seen: the key is the pictures' bytes, the document context, the image prompts and the pool's vision models (not the file name, so the same picture elsewhere is reused).
- API keys are also read from `GOOGLE_API_KEY` (before `GEMINI_API_KEY`, as Google's SDK reads it), `ANTHROPIC_AUTH_TOKEN` (a gateway token, sent as `Authorization: Bearer`) and `OR_API_KEY`, the names LiteLLM and Python markitai read; each also lets its provider join the automatic model pool.
- The Python wheel installs the commands `markitai`, `mkai` and `markitai-mcp` (and runs `python -m markitai`), as the Python markitai package did, so `pip install markitai` gives the command line again: each runs the same program as the `markitai` executable, which the wheel's native extension now carries (the command-line crate is a library the executables and the extension share), and ends with its exit status. Python markitai's extras (`ocr`, `serve`, `mcp`, `claude-agent`, `copilot`, `browser`, `extra-fetch`, `svg`, `heif`, `legacy`, `all`) are kept as names that add nothing, so `pip install "markitai[serve]"` still resolves.
- Python API: `markitai.ConfigFileError` (also in `markitai.api`), Python markitai's error for a bad configuration, is raised for one; it is a `ValueError` subclass, so `except ValueError` keeps working. `await markitai.fetch.close_shared_clients()` (a no-op) and `markitai.utils.shutdown.finalize_process(code)` (flushes both streams and ends the process with `code`) can be imported as before.
- `--text-only` (`output.text_only`; the workbench's Text only under Other, `text_only` in job options with `features.text_only`) writes an image or a PDF as only the text recognised in it: no front matter, title heading, picture link, image description or code fence. Local OCR gives its text; a vision model gives its literal transcription (the image analysis's extracted text, requested even without alt or descriptions); a PDF keeps its text's headings and tables and loses its pictures and page-image comments. No picture is published for it, and an image without readable text gives an empty document and a warning.
- A Word or PowerPoint chart stored as an EMF or WMF picture is now drawn as a PNG by LibreOffice, when it is installed (a separate process with a time limit and size limits, cropped to the drawing), so that it is compressed and analysed like any picture; without LibreOffice the file is kept as before, with no notice.
- The workbench's item menu has a JSON entry (shown when the server announces `document_json`, contract v1.19) that saves the document `markitai -f json` writes.
- `-f json` (`--format json`, `output.format`) writes each converted document as JSON with stable, versioned fields: `schema_version` 1.0, `tool` (version, commit), `source` (path or URL, type, size, SHA-256), `title`, `properties` (the front matter), `markdown.base`/`markdown.llm`, plain `text`, `pages` (number, text, Markdown, pictures, screenshot), `images` (path, alt, description, text read in it, page), `tables` (header and rows), `notices` (a stable `code`, `level`, the message and the pages, pictures or sheets it names), `usage` and `timings`. Every key is always present (`null` when it does not apply) and 1.x versions only add keys; `docs/json-output.md` and `docs/schema/document-v1.schema.json` describe it, and tests pin the field set. Without `-o` the document goes to stdout; with `-o` it is written beside each Markdown file under the same name (`-o x.json` names it), and a batch adds `markitai.index.json` listing every item. `markitai serve` serves each finished item's document at `GET /api/jobs/{job_id}/items/{item_id}/document` (`features.document_json`).
- A subscription provider whose official runtime cannot list models says why: `POST /api/settings/llm/model-discovery` (and the user route) answers `reason` `runtime_missing`, `runtime_unsupported`, `not_signed_in` or `runtime_failed` (also `timeout`) with `runtime` (`name`, `required`, `installed`) and a `next_step` (`install` with the pinned `npm install -g …` command, or `sign_in` with `markitai auth <provider> login`), for Claude, Copilot and ChatGPT alike, instead of `provider_error` for every case. The workbench shows the cause, the command with a copy button and the setup guide, and switches off Add a model by ID for a missing, unsupported or signed-out runtime (a failing one only cautions). Workbench contract v1.18.
- The workbench's submission header has a larger chevron whose whole leading cell (32 × 38 px, 40 × 44 on a phone) opens and closes it.
- The workbench draws mathematics: `$…$` inline and `$$…$$` display formulas (aligned environments included) in Rendered, in headings and in the Contents list. KaTeX 0.19.0 is bundled into a separate `math.js` with its stylesheet and woff2 fonts, all served by the binary and loaded only when a document holds a formula; a formula that cannot be drawn stays as its source, and prices such as `$5 and $6` stay text.
- The workbench's Conversions list can convert again: Re-convert beside Delete in the selection bar (and in a conversion's ⋯ menu) takes the selected kept originals back to the Convert page (uploads are read from the server, pages are re-added by address), opens the options and converts them as a new batch that leaves the first results alone; originals no longer kept are named, and a missing model is said at once.
- A warning mark in the Conversions list shows its notices on hover, focus or tap.
- The workbench's Compare gives a PDF a viewer's toolbar: zoom (Fit width, Fit page, 50–200 %, Ctrl/⌘ + − 0 over the pane), previous and next page with a page box, and an outline panel with the PDF's bookmarks, else the Markdown's headings, else page thumbnails; blocks stay linked at every zoom, and a long PDF's page text is read in the background so linking reaches its last page (it no longer wraps back to an earlier page that says the same). `markitai serve` adds `GET …/original/outline` (`features.pdf_outline`) with the PDF's bookmarks as `{items: [{title, page, level}], truncated}`.
- `markitai serve` gives the workbench's composer its defaults: `GET /api/convert-defaults` answers the server's (its configuration: `llm.enabled`, `ocr.enabled`, `image.alt_enabled`, `image.desc_enabled`, `screenshot.enabled`, `screenshot.screenshot_only`, `llm.pure`, `cache.no_cache`, `image.compress`, `output.profile`, `fetch.strategy`) and, for a user token, its own over them; `PUT /api/convert-defaults` `{expected_revision, defaults}` saves the admin's into `config.json` (only keys the file has or values the built-in defaults do not give) and a user's into its own file (`null` follows the server's again); Cloudflare is never a default (422 `invalid_convert_defaults`), a stale revision is 409 (`features.convert_defaults`). Workbench contract v1.17.

### Changed
- The workbench's Images option Description JSON is now called Image Descriptions (zh 图片描述, ja 画像の説明): it describes pictures and is not the document JSON.
- The static fetch identifies itself as `markitai/<version> (+https://github.com/Ynewtime/markitai)`, with the contact address sites' User-Agent policies ask for (Wikimedia), as Python markitai does, and asks a page answered with 401 or 403 once more with a desktop Chrome's headers before `auto` starts the local browser for it.
- The local browser's render wait ends once the page has settled, as in Python markitai: `fetch.playwright.extra_wait_ms` (3 s) is now an upper bound that ends when no document, script, XHR or fetch request has been in flight and the DOM has not changed for 0.5 s (pictures, fonts, media and event streams are not waited for); a page that fits the window is not scrolled, and the paint pause after scrolling is kept for screenshots only. A page complete at load is read about 4 seconds sooner.
- A fetched URL's response may be as large as a local input file, 500 MiB (it was 100 MiB), as Python markitai allows; a document the local browser downloads stays at 100 MiB.

- A serve retry that loads no page (a fetch-cache hit, or a remote reader without a browser load) keeps the URL item's kept page, its capture record, block boxes and compare screenshots, as Python markitai 1.3.0 does, instead of removing them: the fetch cache is on by default, so a cached retry dropped a good page from Compare. A retry that keeps anything still replaces all of them (workbench contract v1.14, §7 clarification).
- rustls 0.23.46 for RUSTSEC-2026-0346 to RUSTSEC-2026-0349 (TLS secrets in debug output, early data after an ECH rejection, a certificate decompressed before authentication, a key-exchange downgrade), and rustls-webpki 0.103.16 and webpki-roots 1.0.10 for RUSTSEC-2026-0382 and RUSTSEC-2026-0381 (distrusted intermediates, among them emSign's, were accepted); compatible dependencies are updated with them.
- zip 9.0.5 for RUSTSEC-2026-0367 to RUSTSEC-2026-0369 in zip 8.6 and 2.6 (archive extraction, which Markitai never calls); the Numbers reader's iwork 0.2.1 is vendored so it uses the same zip.
- `serve`: a user token's connection can no longer stand in for one of the admin's. A user could save a connection under the id an admin's shared model links to, and that model then took the user's address, so a key written in the admin's model went to the user's host. The user's and the admin's connections are now kept apart.
- `serve`: every request made for a user token's own models (its conversions, model discovery and tests) reaches public addresses only. The check against the server's machine looked at the written host, so a name resolving to loopback, the server's network or cloud metadata passed; names are now resolved when the connection is made and non-public addresses refused, without a proxy and without following redirects. Shared admin models are unchanged.
- `serve`: Cloudflare processing, billed to the server's account, needs the admin token; a user token's job or retry asking for it is `403 remote_processing_forbidden`.
- The LLM answer cache (`cache.db`, which holds document text and model answers) is created readable by its owner only, like the fetch cache; a cache an earlier version left readable to others is narrowed on the next write, and a link in its place is refused.
- LibreOffice exports (Office screenshots and EMF/WMF pictures) never load content a document links to: a picture linked as a file on this machine or an http(s) address is no longer drawn into the export.
- A local image reference is copied into the output's assets only when it is a picture (an image extension or image bytes) inside the document's folder, so a document saved beside private files can no longer copy one of them; a reference that percent-decoding turns into a root, drive or network share is refused before the file system is asked.
- An EML file with messages nested thousands of levels deep is refused with `nested message depth exceeds 64` instead of aborting the process (CLI, `serve`, MCP and bindings) on a stack overflow: the nesting, including messages inside base64 or quoted-printable parts, is counted before the full parse, and parsed messages are freed without recursion.
- HTML nested thousands of elements deep no longer takes time quadratic in its depth (a 220 KB page of 20,000 nested `<div>`s took about 13 seconds in a debug build, a few hundred KB more would take minutes): while a page is parsed, start tags beyond 512 open elements are dropped with their end tags, as Chromium attaches them at its depth limit, and their text is kept. Pages within that depth parse exactly as before.
- Delimited text, JSON and XML no longer grow without bound for their size. A CSV whose one wide row sits over many short ones keeps the short rows short (Markdown fills them) instead of padding every row to the widest, which made the output the product of the two; JSON whose indentation would pass 64 MiB and eight times the input is shown without indentation, with a warning; an XML outline whose indentation would pass the same limit is refused.
- An email body that names many of markitai's own placeholder prefixes no longer costs one scan of the body per prefix: the unused prefix for unresolved `cid:` pictures is found in one pass.
- A small PDF can no longer exhaust memory through many inflating streams: everything the PDF readers decompress for one document (object streams while it loads, then content, font and image streams) draws from one budget, 64 times the file and at least 1 GiB (`MARKITAI_PDF_DECOMPRESS_MIB` sets it in mebibytes), and each decoder stops at what remains. A stream past the budget reads as undecodable. A limit per stream alone bounds no document and would have refused a large object stream holding the document's metadata, which still converts.
- `fetch.playwright.extra_http_headers` are sent only to the initial navigation origin, like `http_credentials`, instead of to every request the browser makes. A secret among them (an API token) no longer reaches a cross-origin subresource host, a favicon host or a redirect target; a same-origin subresource still receives them, and the automatic English `Accept-Language` for X still applies everywhere.
- A URL fetch whose host is on the public internet now stays there: every redirect, `<meta>` refresh, browser navigation and linked picture is refused if it resolves to a non-public address (loopback, private ranges, link-local such as cloud metadata, unique-local), so a public page can no longer send a conversion into this machine or its network. A deliberately local URL (a loopback or LAN host requested directly) is unrestricted. Image downloads already did this; now the page fetch, its redirects and the browser do too. Such a fetch still goes through `HTTPS_PROXY` or the system proxy: each hop's name is resolved first and refused if any address is not public, and only then is the request handed to the proxy (an earlier build of this change fetched every public URL directly, around the proxy).
- `serve`: a URL job a user token owns (and any retry) reaches public addresses only, from its first host onward, and uses no proxy — the same DNS/redirect/browser-aware policy, so a user token's URL cannot read the server's loopback API, its LAN or a cloud metadata service. The admin's own jobs keep their reach, subject to the public-host rule above.
- Shipped binaries and the Python wheel no longer carry the build machine's paths. The packaging builds pass `--remap-path-prefix` (appended to the existing rustflags, so a configured linker flag is kept), so a release binary's panic and debug paths become `registry/src/...` and `vendor/...` instead of `/home/<user>/.cargo/...` and the checkout path (1,564 home-path strings in the CLI binary became none). The wheel's CycloneDX SBOM, which maturin generates with absolute `path+file://` locators and offers no option to disable, is rewritten so its path-dependency locators are relative, on Windows too (where Cargo writes them as `path+file:///C:/...` URLs). The Go static package's shipped `licenses.json` and `manifest.json` carry repo-relative and registry-relative provenance paths instead of absolute ones.
- Packaging hardening. No workspace crate can be published to crates.io by accident (`publish = false`); the build stamp's `git` calls accept only this workspace's own checkout (so an unpacked source tree inside another repository does not take that repository's commit) and run with `core.fsmonitor=false` so they never start that repository's file-monitor daemon; the wheel build tool (`maturin`) is pinned to an exact version (1.15.0) in CI and in the wheel's `pyproject.toml`, and the package driver refuses another.
- Local OCR keeps a scanned page's structure: headings by size (levels judged across all pages of a scanned PDF, so a section is `##` on every page), list items whose bullets the recognizer dropped (found in the pixels), bold and italic words (measured from stroke weight and slant, word by word), and tables drawn with ruled lines, light gray ones included, with each recognized line in its cell.
- A chart or photograph on a scanned PDF page read by local OCR is cut out of the page and written as a picture where it stands, without its axis numbers and legend repeated as text, and the whole-page scan is no longer appended once text was read from the page.
- `serve` Compare links Markdown blocks to their place on scanned PDF pages too: `…/original/pages/{n}/text` answers an OCR'd page with the recognized lines and cut-out pictures (`source: "ocr"`, native pages `source: "text"`).
- Document JSON (`-f json`) gives the whole-document "PDF is scanned: …" notice the code `pdf.page_without_text` instead of `other`, and the notices for several PDF pages (`PDF pages 3–5, 9 (4 of 120): …`) their page codes (`pdf.page_without_text`, `pdf.page`) instead of `other`; `items` lists every page such a notice names, not only its first range.
- `markitai cache stats --json` on a home without `cache.db` or `fetch_cache.db` reports each as an empty store (`count` 0, `size_bytes` 0, `size_mb` 0.0, `max_size_mb` and `db_path`; `by_model` {} and `entries` [] with `-v`) instead of `null`, so `jq .cache.count` gives `0`; inspecting still creates neither file.
- `--profile okf` front matter starts with `type` again and follows Python markitai's order: `type`, `title`, `description`, `resource`, `tags`, `generated` (`by`, then `at`), then the other fields; it was written `title`, …, `generated`, `resource`, `type`, which mattered to readers that check the first line.
- `image.format: webp` honours `image.quality`, as in Python markitai 1.2, instead of writing every picture as lossless WebP (several times larger than Python markitai 1.2's output; 398 KB where 1.2 wrote 54 KB for a sample photo). This build has no lossy WebP encoder, so below quality 100 pictures and PDF/Office page screenshots without transparency are written as JPEG at that quality, named `.jpg` in the files, links and model requests (108 KB for that photo), with one warning per document (`image.webp_as_jpeg`); pictures with transparency, and everything at quality 100, stay lossless WebP.
- A URL that redirects no longer hands its address to the next site: markitai's own HTTP requests send no `Referer`, so a token, key or signature in the original query is not passed to a redirect target on another host (reqwest sent the full previous URL; Python markitai sends none).
- A secret in a URL's path, such as the token in `/reset/<token>`, a `token=…` segment or a long random-looking segment, now reads `REDACTED` in `--json`, front matter, `serve` item names, history, reports and MCP, as it already read `[REDACTED]` in the log; the log, output metadata and the fetch policy use one judgement, and a short code after a route such as `/verify/` or `/invite/` (`/verify/123456`) counts. In `serve`, such a URL's address is kept only by the running server, so retrying it after a restart is refused as for a URL with userinfo. The log no longer hides ordinary segments such as percent-escaped words.
- Query and fragment parameters named `pass`, `pw` or `passphrase` are treated as secrets: their values are redacted in output and messages, and such a URL is not sent to remote fetch services.
- A CSV or TSV fetched from a URL becomes a Markdown table again, as in Python markitai 1.2: `text/csv`, `application/csv` and `text/tab-separated-values`, reStructuredText, Org, LaTeX and notebook types, and a `text/plain` response whose path ends in one of those extensions (as raw-file hosts serve them) are read by the local reader for that format instead of being kept as raw text.
- PDF superscripts, subscripts and footnote marks set off the line by reportlab (`<super>`, `<sub>`) and LibreOffice (footnote anchors) stay on their words again, as in Python markitai 1.2 (`70 m²`, `hourly¹`, `CO₂`), instead of being dropped or moved to the start of the next line (`70 m`, `2 Water covers…`, a line of `3 4`); a footnote's raised number at the foot of the page is no longer removed as a page number.
- A two-column PDF no longer splits a paragraph after a line of the left column that ends in a full stop when the next word could not have fitted on it: the line is measured against its own column, not against a title centred across both columns.
- PDF text keeps a hyphen set between spaces as printed, as Python markitai 1.2 does (`Monday - Friday`, `Harbour Gazette - Spring Issue`), instead of joining the words (`Monday-Friday`), also where the hyphen is drawn as a run of its own, in a line or a table cell; in-word hyphens and words broken at a line end read as before. A running header repeating such a line atop each page is now left out like other running headers.
