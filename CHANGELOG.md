### Changed

- Refresh ten compatible Rust dependency versions, including NAPI, TLS/QUIC support, libc and uuid, while keeping the declared Rust 1.92 minimum and existing Node API level. New NAPI versions retain both original MIT notices with checksum-pinned source and version provenance.
- CLI output ownership uses a stable v2 lock namespace with verified idle-probe cleanup, bounded parent-descriptor reuse and read-only skip planning. Existing v1 namespaces are retained. Trusted current-user directory aliases are accepted while document-file and private-metadata links remain guarded; checkpoint receipts and publication fences continue to protect recovery.
- `config validate` explains explicitly configured keys that have no runtime effect; initialization identifies installed subscription runtimes without launching them or guessing model names. Conversion JSON uses a stable public field order, and oversized XLSX errors suggest CSV export or splitting the workbook.
- Repository text files keep LF line endings on every platform (`.gitattributes`; binary formats are marked binary), so fixtures, help text and embedded workbench scripts are byte-identical on a Windows checkout.
- The minimum Rust version is 1.92 (was 1.89), required by the portable renderer; LibreOffice exports set `XDG_CACHE_HOME` only on Unix, the private profile being `-env:UserInstallation` on every platform.
- Recovery state stores document keys with `/` on every platform, matching batch reports (keys saved with `\` load as the same items); file logs are no longer locked themselves: a running session holds a `<log name>.lock` sidecar, removed when it ends, so live logs stay readable on Windows.
- Program lookup on PATH ignores empty and relative entries, and on Unix requires execute permission; subscription adapter and `auth` tests use Rust stand-ins for the official runtimes instead of Python scripts.
- PDF conversion reads each file, page, font and form once: the page reader, layout reconstruction and Markitai's own inspection share one parsed document whenever both loaders would read the same objects; the inspection hands each page's expanded and parsed content to the page reader and the OCR decision; the encodings and widths of fonts that are indirect objects, and the Form XObjects the text walk follows, are read once per document instead of once per page or call; files under 256 KiB parse on one thread instead of lopdf's global pool, whose idle threads spun; and rectangle clustering skips a size lookup that cannot matter below its cap. Sharing the parsed document cut PDF conversion CPU by about 25% (wall time 6%, large PDFs 14%); on 406 text-layer PDFs the single content read and one-thread loads then cut CPU by 32% and wall time by 6%, and the per-document fonts and forms by a further 1.9% (Form-heavy files about 33%, peak memory unchanged). Every output is byte-identical.
- HTML conversion uses one parser stack, parses each page once and works out what it asks of an element once: a vendored htmd 0.5.5 converts directly over scraper's parsed tree with html5ever 0.39, dropping the second HTML parser stack (html5ever, markup5ever, markup5ever_rcdom and xml5ever 0.38; release binary −215,088 bytes, −0.93%) and building the converter once per process; the cleaner builds the tree htmd renders from directly (pages with inline SVG/MathML, or markup the parser would rearrange, still write and parse markup); attribute lookups compare names, and class tests split class names, without interning them under a global lock, and article-name checks read class and id once per element; whether an element is hidden, page chrome, a note or a note's context is computed once per page, footnote recovery reads the region in one walk, and page metadata and the site readers' checks share one walk. In-process HTML conversion CPU fell 46.8% (1.88×) with the single parse and attribute lookups and a further 24.9% with the per-element facts (e-mail files 15.8%); directory conversions of 1,521 pages fell 15.8% in CPU and 12.3% in wall time, then a further 6.4% and 4.6%. 2,049 HTML, e-mail and EPUB inputs convert byte-identically.
- Keep every acknowledged output on stable media with fewer flushes. On macOS, output publication stages are ordered with `F_BARRIERFSYNC`, with one full-cache flush kept before a success is acknowledged, and adjacent path checks are answered with one ancestor walk: single-file `-o` conversions are about 6 ms (≈33%) faster and directory runs 14–24% faster; Linux keeps its per-object `fsync` sequence. Run-state, report, history and asset writes use barriers where only their order matters and one full flush where a step is acknowledged: directory runs are 16–36 ms faster, and runs with reports and history 110–169 ms (40–47%) faster. A single conversion into a fresh output directory issues 3 full-cache flushes instead of 10: its claim directories are created first and share one media fence per volume, with the same per-level checks and host synchronization, before any lock or work (single-file conversions on corpus-r4 23–36% faster; existing output directories are unchanged). A run's missing output directories are made durable before name reservation with one shared macOS full-cache flush per volume instead of two flushes per directory, and recovery-state directory creation shares one flush too; recovery-state validation reuses one filesystem observation per operation instead of re-walking the same path ancestors for every saved path, halving a directory run's `lstat` calls. Controlled output metadata initialization and dispatch admission are persisted in bounded windows, and directory and URL-list items publish in bounded groups that share macOS full-cache flushes while keeping durable receipts, recovery ordering and paid failure usage. Outputs, ownership records and state stay byte-identical, and every host synchronization, directory identity, the original skip path and the no-work-before-commit rule are kept.
- Link the macOS frameworks behind OCR, HEIF/AVIF decoding and PDF rasterization delay-initialized in the command-line executables, the Node addon, the Python extension and the C library (and so the dynamically linked Go package). On macOS 15 and later, conversions that need none of them start about 1 ms (≈25%) faster, loading the Node addon takes 3.6 instead of 4.9 ms, the Python extension 1.5 instead of 2.3 ms, and a Go program starts in 5.7 instead of 8.0 ms, with identical output. The static Go package keeps ordinary links because cgo rejects the flag; its users can opt in through `CGO_LDFLAGS`. The documentation explains why the first OCR after an install takes 25–45 seconds (Vision compiles its models per executable).
- Python: `import markitai` takes 1.9 instead of 20.8 ms in process (12.4 instead of 34.4 ms for a whole interpreter): asyncio loads only for `aconvert` or a running loop, and dataclasses, json, pathlib and the configuration models on first use, with the public names, pickling and type stubs unchanged.
- Shrink the release binaries with every corpus output byte-identical. Sorts go through a few shared entry points instead of one monomorphized sort per closure: in pdf-inspector a type-erased stable sort and two float orders, with keys precomputed in a few Markitai sorts (sort code 1.45 MB → 0.68 MB, release binary −826,176 bytes or −3.6%, no slowdown), and later one shared total-order sort per crate in markitai-core, anydoc, lopdf and the CLI. PDF glyph names are found by binary search in packed tables built at compile time: in a vendored lopdf 0.45.0 instead of a 4,495-arm `match` of 531,880 bytes of code (−462,352 bytes, −2.0%, speed unchanged within noise) and in pdf-inspector instead of a 4,528-entry map filled at first use, 108,960 bytes of code (−82,576 bytes), both checked on 216 corpus PDFs and every glyph name. `zip` keeps the same flate2/zlib-rs deflate backend without the zopfli encoder, which it uses only above level 9 and Markitai never requests (−82,800 bytes; 982 inputs convert byte-identically). Native Linux builds pack relative relocations (DT_RELR) when the linker and C library support them; with more sort code shared across the CLI and pdf-inspector, this took 1,174,904 bytes (−4.4%) off the Linux CLI and 231,360 bytes off the macOS one. The last round's shared sorts, collections built by inserting instead of sorting collected pairs, one reader type for every image and TIFF decode (the PDF embedded-image size probe included) so the decoders are compiled once, and one boxed task type each for the server's blocking and spawned tasks saved about 0.5 MB: with that round's features included, the macOS arm64 release CLI went from 21,980,096 to 21,549,968 bytes.
- Build `markitai-ffi` only as `cdylib` and `staticlib`, so the release profile's link-time optimization applies to both: on macOS arm64 the static archive shrinks from 219.8 to 34.5 MB and `libmarkitai_ffi.dylib` from 18.06 to 16.94 MB, and statically linked Go programs from about 48 to 25 MB.
- Make CLI messages say what happened and what to do next: help is grouped, wraps to the terminal's width (clap `wrap_help`; 100 columns when not on a terminal), ends with presets, examples and exit codes, and describes every subcommand option; a file that cannot be converted is answered with every supported document and image extension, as the reference does; a skipped image says why and what to enable; `-o` reports the path written; unusable output paths, unreadable inputs, empty directories, unknown presets, `--json` without `-o` and invalid `.urls` entries are reported with the path or entry number before any output directory is created; a batch closes with what was converted, how long it took and what it cost, skipped items by reason with the next step, failed and unfinished counts, failed examples and the output directory; a failed web request says why (a refused connection, a name that does not resolve) instead of only "error sending request", without the URL; `doctor` accepts a model configured through the environment; an unusable `MARKITAI_BROWSER_EXECUTABLE` is named instead of reporting Chromium as missing; a refused symlink points at `output.allow_symlinks`; `config set` no longer echoes unset fields as redacted; cache sizes read in KiB/MiB; and empty runs report `0.0` and MCP jobs without costs `0`, instead of `-0.0`.
- Match the reference's document tails and spacing: legacy DOC/PPT, RTF, ODT and ODS Markdown ends with a newline, headings drop trailing spaces, and presentation output collapses blank runs from text-free shapes and trailing whitespace. On the reference's 20 non-HTML fixtures, 16 now match byte for byte; the rest are the accepted asset names and the recorded EPUB-anchor, ODS-span and PDF-layout differences.
- Render HTML callouts and alerts (Obsidian, GitHub, Bootstrap, callout asides, Hugo/Docsy admonitions) as `> [!type] Title` blockquotes keeping collapsed bodies, TeX image-service images as `$…$`/`$$…$$` math, and lists, rules and empty quote lines in the reference's spelling (`* item`, `1. item`, `---`, `>`).
- Render EML downloads in `## Attachments` with their size, and quote attached messages one level deep with nested attachments listed by name; an empty body leaves a bare `## Content`. Body Content-ID images stay bound, with a separate preview when their original is also a download.
- Report a web page's `word_count` in URL frontmatter (each CJK character one word, as the reference counts), and keep the internal reader identity (`converter`) out of user-facing URL frontmatter.
- Use `sha2` 0.11, whose SHA-256 selects the CPU's SHA instructions at run time on aarch64 and x86, for content proofs, cache keys and asset names; digests and their spelling are unchanged, and the duplicate `sha2` 0.10 is gone.
- Warn about PDF image placement only when images were extracted, without the obsolete claim that page screenshots and local OCR are not implemented.
