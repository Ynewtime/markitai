# 转换性能

完整短文与中日韩正文可直接完成本地静态提取，避免不必要的浏览器启动。
公网 URL 在 Fake-IP 代理环境下，也可在通过[抓取策略](./fetch-policy)中的
公网 DNS 校验后使用显式选择的远程读取器。

本地文件按需加载后端。普通 Office 文档使用专用路径，复杂内容、公式和
含歧义的表格值保留兼容回退。图片、元数据、错误处理和调用方定制适配器
仍属于输出契约。PDF 模型配置没有改变。

## 实测结果

2026 年 9 月，在 macOS、Python 3.12 环境下，相对冻结的优化前源码快照，
综合提速约 **6.01×**：

| 等权负载 | 提速 |
| --- | ---: |
| 通过本地 HTTP 获取的五个 URL 页面 | 5.83× |
| DOCX、XLSX、PPTX、PDF 的冷 CLI 转换 | 5.61× |
| 30 个 TXT/HTML/DOCX 文件的批处理 | 6.64× |

综合指标为三个组的几何平均，每项运行三个新进程。该结果关闭模型增强和
远程抓取，不包含公网时延、远端缓存、LLM 响应或 OCR 的影响，也不保证任意
大小文档都达到相同倍数。

审计同时检查完整产物：40 项转换器/API 快照、额外 23 个复杂表格样例和
208 个网页样例。更广泛的测试还覆盖复杂 DOCX 回退和运行时适配器定制。

复现命令、评分口径与输出质量检查见仓库中的
[基准指南](https://github.com/Ynewtime/markitai/blob/main/scripts/benchmarks/README.md)。

## 排查慢速转换

用 `-v` 查看选中的策略及回退原因。`--no-cache` 关闭的是 Markitai 缓存，
无法关闭远端服务的缓存。已运行的远端读取器与刚启动的本地 CLI 承担的
工作不同，不能直接把差值全部归因于提取算法。

测量纯本地转换时可用 `--preset minimal --no-remote-fetch`；评估实际完整
工作流时，应保留平时使用的模型增强、OCR 等选项。
