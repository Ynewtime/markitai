# 网页工作台

`markitai serve` 在本机打开一个网页工作台，用来转换文件和 URL。拖入文件或文件夹、粘贴链接、看进度，逐条查看结果并与原件对照预览，再下载全部输出。支持中文、英文和日文，桌面和手机都能用。

一切都在本机运行。任务和历史保存在磁盘上，除了你配置的抓取策略和 LLM 提供商，不会向外发送任何内容。

## 启动服务

装上 `serve` extra，然后启动：

```bash
uv tool install "markitai[serve]" --force
markitai serve
```

浏览器会自动打开 `http://127.0.0.1:3600`。

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--host` | `127.0.0.1` | 绑定的网卡。要让其他设备访问，用 `0.0.0.0` |
| `--port` | `3600` | 监听端口 |
| `--no-open` | 关闭 | 启动后不打开浏览器 |
| `--no-auth` | 关闭 | 禁用访问令牌 |
| `--allowed-host <hostname>` | — | 通过域名而非 IP 访问时，额外放行的主机名（可重复） |

## 访问令牌

启动时服务会打印一个以 `#token=…` 结尾的 URL，自动打开的浏览器用的也是这个 URL。本机请求不需要令牌，但 LLM 设置（`/api/settings/llm…`）除外：这些接口存放着提供商密钥，而本机任何程序、另一个 `localhost` 端口上的网页同样是从本机连进来的，所以这些接口始终要求令牌。其他设备必须打开这个 URL，脚本则以 `Authorization: Bearer <token>` 发送令牌。服务端看不到客户端地址的请求按其他设备对待。

没带令牌打开的标签页会在需要时提示输入（**系统设置 → 访问令牌** 为该标签页保存令牌）。浏览器发起的下载使用一分钟内有效、只能用一次的链接，令牌本身不会出现在 URL、浏览历史或下载列表里。

**系统设置 → 访问令牌 → 重新生成令牌…** 会替换令牌：其他所有标签页和设备（包括本机）都要重新登录，尚未使用的下载链接也随之失效。新令牌只显示一次，附带登录链接和二维码；和启动时的令牌一样，它在服务器停止前有效。**退出此标签页**只清除该标签页保存的令牌。

**系统设置 → 访问令牌 → 用户令牌**可以为其他人或设备单独发放令牌：填写名称后点**创建令牌**；令牌只显示一次，附带复制、登录链接和二维码，之后在列表中按末尾几位字符显示，并显示最近使用时间。用户令牌可以转换文件和 URL（仅限公网地址：它的 URL 和它的文档引用的图片不会从服务器所在的网络抓取；而且不论 `fetch.remote_consent` 怎么设，都不会经由远程读取服务 defuddle.md、Jina Reader 或 Cloudflare：本地策略拿不到页面时，该条目会说明跳过了远程回退），但只能查看、下载、停止、重试和删除自己的转换；模型、访问令牌和编辑配置需要服务器的令牌（管理员令牌，或本机不带令牌访问），用用户令牌登录的标签页在这些页面会说明这一点，系统设置里显示外观和它自己的模型（见[用户的模型与共享模型](#用户的模型与共享模型)）。管理员能看到所有人的转换。**撤销**会立即让用户令牌失效，连同它的下载链接和实时进度，本机也一样。每个用户令牌只保存 SHA-256 摘要，存放在 `~/.markitai/serve/access.json`（只有你的用户可读，从不写入配置文件），因此重启和重新生成管理员令牌后依然有效；服务器日志只记令牌名称，从不记录令牌本身。

设 `MARKITAI_SERVE_TOKEN` 可以让令牌在重启后保持不变。`--no-auth` 完全去掉令牌：其他设备仍能上传、下载和查看历史，但不能提交 URL（公网和内网地址都不行），也不能改 LLM 设置。此时本机不带令牌即可使用 LLM 设置。

## 从其他设备访问

绑定全部网卡，再在手机或另一台电脑上打开打印出来的令牌 URL：

```bash
markitai serve --host 0.0.0.0
```

如果你用域名而不是 IP 访问，加上 `--allowed-host my-box.lan`。服务会拒绝未知主机名，挡住恶意网页的 DNS 重绑定攻击。

::: warning
令牌 URL 就是凭据。拿到它的人可以用你的 LLM 提供商发起转换，还能查看、下载和删除历史。只分享给你信任的设备。
:::

## 工作台功能

侧栏分三处：**转换**、**转换任务**和**系统设置**（外观与语言、模型、访问令牌、编辑配置）。在手机上它们移到底部栏，转换以全屏窗口打开。它们下方有一行说明当前应答的服务器构建：版本、构建所用的提交（构建含未提交改动时带 `-dirty`）以及按你所在时区显示的构建时间（`1.2.1 1a2b3c4 10-15 09:30`；悬停可看完整时间）。从源码检出运行的服务器没有构建时间。

- **输入区**：粘贴 URL（每行一个），拖入文件或文件夹，或用**上传**（下拉菜单可选文件夹）。文件先暂存，按下**转换**才提交，带上传进度，可以和 URL 合成一次提交。`.urls` 文件按 URL 列表读取，与命令行一致。URL 在发送前就会校验。
- **选项**：默认什么都不问。**选项**里有预设、增强（LLM、OCR、图片分析）、输出（profile）和高级（抓取策略、文件后端、缓存、压缩），并附上等价命令行，可直接复制。 选项从**服务器的默认值**开始（`config.json` 叠加内置默认值：`llm.enabled`、`ocr.enabled`、`image.alt_enabled`、`image.desc_enabled`、`screenshot.enabled`、`screenshot.screenshot_only`、`llm.pure`、`cache.no_cache`、`image.compress`、`output.profile` 和 `fetch.strategy`，命令行读取的也是这些键）。命令行上方一行会说明它们是服务器的、你的还是已改动的，并提供**恢复默认值**和**存为默认值**：管理员的选择写入 `config.json` 并立即用于下一次转换，用户令牌的选择保存在它自己的文件里（**使用服务器的默认值**可撤销）。Cloudflare 永远不会成为默认值。
- **转换任务**：一个列表列出所有条目，按提交分组（以来源文件夹或 `.urls` 列表命名），实时更新，可按名称筛选，或按全部、失败、有提示过滤。要一次删除多个，用行或提交标题左侧的勾选框选中它们（空格勾选当前行，Shift 扩展选择，Ctrl/⌘+A 勾选所有列出的行，Esc 清除；手机上先点**选择**），再点出现的底部栏里的**删除**并确认；仍在转换的条目不能勾选。**停止剩余**会停下正在运行的提交里尚未开始的条目，已在转换的条目照常完成，被停下的条目之后可以重试；在手机上，它一直在盖住列表的全屏窗口标题栏里。**新建转换**回到转换页，“⋯”里有**重试失败**和**全部下载**。提交在后台标签页完成时会发通知。
- **转换窗口**：点击条目（或在条目上按 Enter）会在列表上方打开它的窗口，有三个标签：**详情**、**预览**和**对照**。↑/↓ 或窗口标题栏的箭头切换到上一个或下一个条目，**C** 切换到对照，Esc 关闭。窗口的放大按钮（或 **F**）让它占满浏览器并还原（每个浏览器记住这个选择）；在手机上窗口占满屏幕。**详情**显示条目的状态、原件与输出的大小、使用的模型与费用、选项、保留期限和提示，以及结果开头。标题栏有**下载**（打开预览的**文件**），需要时还有**重试**；“⋯”里有**用 LLM 增强**、**重新运行**和删除。markitai 无法转换的文件类型不提供重试。对条目的操作失败时（例如服务器拒绝了重试），原因显示在详情顶部。
- **费用**：只有确知的费用才会显示金额。提供商没有给某个模型定价时，条目显示费用未知，而不是 `$0`；只有部分请求有价格时显示“至少”多少。
- **预览**：窗口的第二个标签，有渲染、源码、文件，LLM 增强过的条目还有与未增强 Markdown 的对比；它的“⋯”里有复制和导出 PDF，页眉页脚可选。**文件**先列出原件，再列出每个结果文件，各自可下载，并提供**全部下载（.zip）**，包含结果和原件。网络图片（Markdown 中的绝对 `https://` 地址）会直接显示，且不发送来源页信息；其他地址显示为带说明的占位符。以带链接的封面图写出的视频（`[![Video](poster)](https://…/clip.mp4)`；`.mp4`、`.m4v`、`.webm`、`.mov`、`.ogv`）可以直接播放：播放前不加载任何内容，无法播放时恢复为链接。单元格里残留的换行打断的表格行会被重新拼好；源码视图保持原文。大表格先显示前 500 行（**显示全部行**加载其余），代码块带语法高亮。
- **对照**：在 Markdown 旁显示原件：PDF 的页面（鼠标移到 Markdown 里的标题或表格上，页面上会框出对应位置）、图片、HTML 或文本文档，或转换时保存的页面截图（Office 文件、网页）。浏览器无法显示的格式改为提供**下载原件**。网页按服务器抓取到的样子显示在沙箱框架中：带有网站自己的图片、样式表和字体（由浏览器经 HTTPS 从网站加载），不运行它的脚本，链接在新标签页打开（保存了截图时可与截图切换）；在任一侧悬停标题、段落、列表项、表格或图片，另一侧对应的部分会被框出，网页和截图上都是如此。浏览器加载过的网页即使没有要求截图也会保留一份截图（对照用的副本，不属于输出，也不会发送给模型）。对照视图只显示真正呈现了网页的视图：网站返回验证检查或空白页时，会说明原因并提供打开原网页。经 Jina、Defuddle 或抓取缓存得到的页面不保存，改用截图。
- **提示**：不会让条目失败、但值得处理的情况（页面疑似扫描件、PDF 隐藏文字可能是提示注入、OCR 没识别出文字、幻灯片无法渲染、URL 截图没拍到、图片分析失败而保留了原来的 alt 文本、LLM 增强失败而保留了未增强的结果）会计入条目并在详情里列出，同一种提示合并显示，页码以区间列出（`pages 3–5, 9`）。不少于九成页面没有可读文字的 PDF 提示 "This PDF is scanned: turn on OCR and convert again"；否则列出没有文字的页（"Pages 3–5, 9 (4 of 120) have no readable text…"）。与文档逐页对不上的模型回答会照此说明，并保留转换得到的 Markdown。每个条目只收到自己的提示，任务进入历史后也会保留。
- **下载**：单个文件、一次提交的 zip，或用转换任务“⋯”里的**全部下载**打包所有内容。
- **限制**：每个任务最多 1000 个条目，单个上传文件最大 100 MB，一次上传总共最多 5 GB。

### 预设、覆盖与命令

预设和 CLI 一致：

| 预设 | LLM | alt | desc | screenshot | OCR |
|------|:---:|:---:|:----:|:----------:|:---:|
| `minimal` | – | – | – | – | – |
| `standard` | ✓ | ✓ | ✓ | – | – |
| `rich` | ✓ | ✓ | ✓ | ✓ | – |

没有预设会开 OCR，OCR 始终要你单独勾选。选一个预设会重置这五个开关；单独改一个开关则保留其余，并显示为**自定义**。

每个选项都有悬停或轻触帮助，说明它依赖什么、数据去哪、可能花多少钱。

## LLM 设置

**系统设置 → 模型**编辑的就是 `markitai config` 那套配置：发现提供商、浏览模型列表、设置权重、测试连接，且不会暴露已保存的 key。**添加模型**会打开服务商选择器：可按名称或模型前缀搜索，常用服务商以卡片列出，其余按分组筛选（云平台、推理服务、网关、本地、订阅、模型厂商）。markitai 能经 LiteLLM 调用的服务商都在其中，约 90 个，各自标明所用地址和读取的 key 变量；填入 key（自建服务器还要填地址）后，从服务商的模型列表中挑选，服务商不公开列表时手动输入模型 ID。改动同时作用于网页任务和之后的 CLI 运行。

服务器设置了某个服务商的 key 变量（`OPENAI_API_KEY`、`DEEPSEEK_API_KEY`、`GROQ_API_KEY`、`MOONSHOT_API_KEY` 等，选择器里的任何服务商都可以）时，选择器会把它和已保存的连接列在一起（“使用 OPENAI_API_KEY”）；已在服务商自己的端点使用该变量的连接（例如配置里没写 key 的手写模型）会代表它，因此每个服务商只占一行，常用服务商卡片标为**已添加**。它的模型用这个 key 从服务商自己的端点列出，从它添加的模型只保存引用 `env:OPENAI_API_KEY`，不保存 key 本身；之后由这个已保存的连接代替这张卡片。这个 key 只发往它所属服务商的端点：要用别的地址，请输入 key 来连接该服务商。

测试模型失败时会说明原因：没有 API 密钥（服务器上没有设置 key 变量，这时什么都不会发送；在运行 `markitai serve` 的地方设置并重启，或者给这个连接填入 key）、key 被拒绝（HTTP 401/403）、服务商没有这个模型、服务商在限流或额度不足、连不上服务商、服务商没有及时响应，或服务商返回了其他错误。服务商自己的原话放在“服务商原文”下。API 用 `reason` 给出同样的类别（`no_key`、`key_rejected`、`model_not_found`、`rate_limited`、`network`、`timeout`、`provider_error`），缺少 key 时用 `key_variable` 给出变量名。

提供商编辑器只显示已保存 key 的打码形式（`sk…7890`；`env:` 引用原样显示）。不动这个字段就保留已保存的 key，输入新 key 即替换，清空则删除 key。已保存的 API 基础地址显示时不含凭据（`https://…@proxy.example/v1?api_key=…`）：保持原样即沿用已保存的地址，要修改请输入完整地址。

key 和保存时的地址绑定在一起，所以设置页面不会把你没输入过的 key 发到你指定的服务器。以下操作会被拒绝（HTTP 422）：把 `env:` 引用和自定义地址配在一起；使用提供商 key 变量（`OPENAI_API_KEY`、`DEEPSEEK_API_KEY` 等）以外的 `env:` 变量；修改某个连接的地址却不重新输入它的 key。需要这样配置时，要么连同新地址直接输入 key 本身，要么在配置文件里写好这一对（用 `markitai config edit` 或手动编辑，见[自定义 API 端点](/zh/guide/configuration#自定义-api-端点)）。配置文件里已有的组合在设置页面照常可用。

在这里保存的连接如果没有 key 却指定了地址（本地服务器、网关），会保存占位 key `markitai-no-key`，任何服务器都不会把它当作凭据：没有它，LiteLLM 会读取服务器自己的 key 变量（`OPENAI_API_KEY`、`GROQ_API_KEY` 等）并发往那个地址。不校验 key 的服务器（LM Studio、vLLM、llama.cpp）照常可用；设置页面把这样的连接显示为没有 key。已有 key 的连接不能改成指向另一个地址的无 key 连接（HTTP 422）：请为那台服务器新建一个连接。你在配置文件里自己写的条目不受影响：没有 `api_key` 的条目仍从环境变量读取该提供商的 key。

Vertex AI（以及 watsonx、GigaChat）用服务器自己的登录凭据而不是 key 认证：Google 应用默认凭据（`gcloud auth application-default login`、`GOOGLE_APPLICATION_CREDENTIALS`）、`WATSONX_TOKEN`、`GIGACHAT_ACCESS_TOKEN`。LiteLLM 会把这些凭据发往条目指定的任何地址，所以设置页面只在不带地址时保存和测试这些模型，即使用服务商自己的端点（否则返回 HTTP 422）：**添加模型**不为 Vertex AI 显示地址栏，并注明它使用服务器的 Google 登录；私有端点请写在配置文件里。Amazon Bedrock 可以带地址：没有 key 时它发往那里的是占位 key，从不发送服务器的 AWS 凭据。

### 用户的模型与共享模型

用户令牌在**系统设置 → 模型**中管理自己的模型（同一个页面，没有配置文件那一行，也没有检测到的模型）：添加模型、测试、编辑、删除和设置权重。每个已保存行的权重都可以直接修改：点击它，输入 0 到 100 的整数，按 Enter 或离开输入框即保存，Esc 取消（管理员的行也一样）。这些模型保存在 `~/.markitai/serve/user-models/<令牌 id>.json`（只有你的用户可读，从不写入配置文件，所以编辑配置和命令行都看不到），只用于该用户的转换，密钥只以打码形式显示。用户只能添加带自己 API key 的模型，或不需要 key 的服务器地址（保存为 `markitai-no-key`）；服务器会拒绝用其自身账号或云登录认证的服务商（Claude Code、Copilot 和 ChatGPT 订阅、Vertex AI、watsonx、GigaChat、SageMaker、不带 key 的 Bedrock）、`env:` 引用，以及指向服务器本机的地址（`localhost`、`127.0.0.1`、`::1`、`0.0.0.0`；所以 Ollama 或 LM Studio 需要用户自己的地址）；最多 50 个模型。除此之外，为用户自己的模型发出的每个请求（它的转换、模型发现和测试）只能到达公网地址：建立连接时才解析域名，公网以外的地址（回环、内网、云元数据这类链路本地地址、唯一本地地址）一律拒绝，所以指向服务器本机或其网络的域名同样会失败；不跟随重定向，会经环境代理发出的请求也被拒绝，因为地址由代理决定。管理员共享的模型不受此限制。

管理员保存的模型默认是**私有**；设为**共享**后，所有用户的转换都可以使用它（在配置文件中保存为 `"model_info": {"share": "shared"}`）。用户在**管理员共享**下只能看到共享模型的模型 ID、服务商和权重：它的 key 和地址留在服务器上，用户看到的失败信息也不会说出它在哪里提供服务。用户的转换使用一个模型池：自己的模型和共享的模型按权重选择，请求失败时换用池中另一个模型；提示词、预算和缓存仍是管理员的设置，任务会显示用了哪个模型和费用。两者都没有的用户没有 LLM 选项，请求 LLM 会被拒绝（`llm_unavailable`）：服务器的环境变量 key 和检测到的模型从不为用户服务。把模型改回私有对下一个请求立即生效。

每个共享行有 **测试** 和一个属于该用户自己的权重。这个权重只作用于该用户自己的转换：设为 0 表示该用户不再使用这个共享模型，其他用户和管理员不受影响；**Use the admin's N** 恢复跟随管理员的权重（保存在用户自己的文件中，字段为 `shared_weights`）。测试在服务器上用管理员的密钥和地址进行，只说明模型是否通过以及未通过的原因（"请管理员检查"），绝不透露服务商的原话、地址或密钥；因为费用由管理员的密钥承担，每个用户同一时间只能运行一个这样的测试，每分钟最多六次。

用户令牌的 **系统设置 → 编辑配置** 以文本形式编辑它自己的模型：一份 JSON 文档，包含 `models` 和 `providers`（它的条目，形式与 `llm.model_list`、`llm.providers` 相同）以及 `shared`（每个共享模型及该用户为它设的权重），密钥像管理员页面那样以掩码显示，校验、审阅和冲突处理也相同。服务器的配置文件绝不会向用户显示，也不会被用户修改；用户保存的内容同样受上述规则约束。**系统设置 → 访问令牌**显示每个用户有几个模型；撤销令牌会连同 key 删除这些模型（删除时服务器若被停止，下次启动时会删除）。

## 编辑配置

**系统设置 → 编辑配置**以文本形式显示服务读取的配置文件（也就是 `markitai config` 编辑的那个），其中的密钥按 `markitai config show` 的脱敏规则遮盖：API key、令牌、密码、cookie 等密钥类键名下的值，以及所有 HTTP 请求头的值，都显示为 `sk…7890` 的形式；`env:` 引用照原样显示；已保存的地址不显示其中的凭据。输入时检查 JSON（报告行和列），**查看修改**以逐行差异显示，**保存配置**原样写入查看过的文本，保留排版、键的顺序和换行符（Windows 上写的文件仍是 CRLF，页面会说明）。留在原处的遮盖值会保留已保存的密钥；要修改，请输入完整的新值或一个 `env:` 引用。如果页面读取之后文件被改动过，保存会被拒绝，**加载当前文件**会重新读取。模型和连接立即生效；其他改动需要重启时页面会说明。

## 历史记录

完成的任务在 `~/.markitai/serve/jobs/` 下保留到完成后 7 天（详情标签显示具体日期）；到期的任务立即从列表消失，其文件在一小时内删除。刷新页面或重启服务后，任务仍在**转换任务**里：可以重新打开、再次下载输出、重试或增强其中的条目、删除，或把全部内容打包下载。

用 [`--record-history`](/zh/guide/cli#record-history) 启动的 CLI 运行也会出现在这里，带一个 CLI 徽标。它们和其他任务一样可以打开、下载和删除，其中的 URL 条目也能重试或做 LLM 增强。CLI 运行里的文件条目不能在这里重试或增强：CLI 只保留了输出，没有保留原文件；需要的话请用 CLI 重新转换该文件。

`--llm-batch` 运行如果在提供商批处理仍在进行时停止等待，这些条目会记为跳过，原因显示为 *LLM 批处理仍在进行*，历史里暂时只有基础 Markdown。请用那次运行打印的 `markitai --llm-batch-collect` 命令收取结果，不要在这里再做增强，否则同一份增强会付两次费。

## API 概览

工作台建立在一套小型 REST + SSE API 之上，脚本也能直接调用。错误响应是 JSON `{"detail", "code", "reason"}`：`detail` 是英文说明，`reason` 是稳定的原因代码，例如 `llm_unavailable`、`file_too_large`。

| 端点 | 说明 |
|------|------|
| `GET /api/capabilities` | 服务版本与构建（`build: {version, commit, built_at, dirty}`）、预设、LLM 与 extras 状态、限制与支持的功能 |
| `POST /api/jobs` | 创建任务（multipart 表单：`files`、`urls` JSON 数组、`options` JSON，可选 `label`）。`.urls` 文件展开为 URL 条目。要求 LLM 处理却没有可用模型时直接拒绝（`llm_unavailable`） |
| `GET /api/jobs/{job_id}` | 任务状态与条目（每个条目带 `warnings`、`error_code`、`page_sources`（PDF 每页文字的来源，其他条目为空），用过模型时还有 `pricing`） |
| `GET /api/jobs/{job_id}/events` | 实时进度流（SSE） |
| `POST /api/jobs/{job_id}/cancel` | 停下尚未开始的条目 |
| `POST /api/jobs/{job_id}/items/{item_id}/retry` | 重试条目（JSON 请求体可选：`operation`、`options`；不带 `options` 时沿用该条目自己的选项），或以 `operation: "enhance"` 做 LLM 增强：除非 `options` 写明 `"llm": false`，它总会开启 LLM |
| `DELETE /api/jobs/{job_id}/items/{item_id}` | 永久移除条目，连同其上传原件、输出、图片与截图 |
| `GET /api/jobs/{job_id}/items/{item_id}/result` | 条目结果（`?max_bytes=N` 只取开头：N 至少为 1024，否则返回 422 `invalid_max_bytes`；最多 N 字节，附近有行尾时在行尾截断，并给出 `truncated` 和完整的 `markdown_bytes`；完整结果超过 64 MiB 时返回 413 `result_too_large`）；配套资源经 `GET /api/jobs/{job_id}/files/{path}` 获取 |
| `GET /api/jobs/{job_id}/items/{item_id}/assets/{path}` | 条目自身提取出的一张图片（PNG、JPEG、GIF、WebP、AVIF），以内联方式返回供显示 |
| `GET /api/jobs/{job_id}/items/{item_id}/original` | 条目原件能显示什么（网页还包括其副本和截图是否可用，`capture`）；`/original/file`、`/original/view`、`/original/pages/{n}?width=`、`/original/pages/{n}/text`、`/original/outline`（PDF 的书签）与 `/original/blocks`（网页各区块在截图上的位置）提供内容 |
| `GET /api/jobs/{job_id}/archive` | 整个任务打包为 zip 下载 |
| `POST /api/download-tickets` | 为一次下载换取一分钟内有效、只能用一次的 `?ticket=` 链接 |
| `GET /api/history` | 列出历史条目（`?include=items` 附带全部条目） |
| `GET /api/history/archive` | 全部历史打包为一个 zip 下载 |
| `DELETE /api/history/{job_id}` | 删除单条历史 |
| `POST /api/history/delete` | 一次请求删除多个任务和条目（`{"jobs": [...], "items": [{"job_id", "item_id"}]}`，最多 1000 项），每项按对应的单个路由处理，应答列出每项结果 |
| `/api/settings/llm*` | LLM 提供商、模型与部署管理 |
| `GET`/`PUT /api/convert-defaults` | 新建转换的选项默认值（所有调用者可读；`PUT` 为 `{"expected_revision", "defaults"}`：管理员的写入 `config.json`，用户令牌的写入它自己的文件，`null` 表示删除） |
| `GET`/`PUT /api/settings/config` | 配置文件文本（密钥已遮盖）；按其 `revision` 原样保存 |
| `GET`/`POST /api/access-tokens`、`DELETE /api/access-tokens/{id}` | 用户令牌（仅管理员；列表给出每个令牌的 `model_count`） |
| `/api/me/models*` | 用户令牌自己的模型，后缀和规则与 `/api/settings/llm*` 相同（其他调用者得到 403 `user_token_required`）；`PATCH /api/me/models/shared/{id}` 设置它对某个共享模型的权重，`POST /api/me/models/test` 带 `{"shared_id"}` 测试共享模型 |
| `GET`/`PUT /api/me/config` | 用户令牌自己的模型，作为一份掩码后的 JSON 文档（`models`、`providers`、`shared`），按模型页的 `revision` 保存 |

服务会拒绝来自其他网站来源的状态变更请求，所以随便一个网页没法借你的浏览器操作它。Cloudflare 处理（`strategy` 或 `backend` 为 `"cloudflare"`）要求同一请求的选项里带 `"remote_processing": "cloudflare"`（工作台在你确认后发送）；由于它计入服务器的账户，除管理员外一律拒绝（403 `remote_processing_forbidden`）：没有令牌的调用方和用户令牌都不行。用户令牌访问设置和令牌路由会得到 403 `settings_forbidden`，访问不是自己创建的转换会得到 404 `job_not_found`；`GET /api/capabilities` 会说明调用者是谁（`access.role`：`admin` 或 `user`）。
